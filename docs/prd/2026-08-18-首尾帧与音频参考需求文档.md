# 创意生成——首尾帧与音频参考需求文档

> 版本：v1.0  
> 日期：2026-08-18  
> 状态：待评审  
> 适用页面：创意助手 / 创意生成 / 视频生成

## 1. 背景

广告客户希望在生成产品视频时：

- 指定视频开始画面和结束画面，提升产品、人物与构图的可控性；
- 上传既有产品广告的 MP3，参考其音色、台词、节奏或背景音乐风格，减少不同批次广告之间的声音差异。

当前创意生成仅提供提示词、模型、Hook、分辨率、比例、时长等设置，缺少“首帧”“尾帧”“参考音频”三个明确入口。

## 2. 目标

在创意生成的视频任务中新增：

1. **首帧图片**：选择 1 张本地图片。
2. **尾帧图片**：选择 1 张本地图片；仅在已选择首帧且当前模型支持时可用。
3. **参考音频**：选择 1 个本地 MP3 文件；仅在当前模型与当前素材组合支持时可用。
4. 根据模型实际 API 能力动态控制入口的可用状态、校验规则与请求映射，不向用户承诺模型未开放的能力。

## 3. 名词与边界

### 3.1 名词

- **首帧**：要求生成视频从指定图片开始，属于严格帧约束。
- **尾帧**：要求生成视频以指定图片结束，属于严格帧约束；不能脱离首帧单独使用。
- **参考音频**：将 MP3 作为模型生成条件，用于参考音色、台词、节奏、动作时序或音乐风格，具体作用取决于模型接口。
- **模型生成音频**：模型根据提示词自动生成声音，与用户上传的“参考音频”不是同一能力。

### 3.2 本期不包含

- 不承诺逐采样复制原音轨，也不承诺 100% 复刻特定人物声音。
- 不包含声音克隆、版权校验、音频剪辑、降噪、分轨和混音。
- 不支持音频 URL、视频文件或商品库音频；本期仅支持本地 MP3。
- 不支持多首帧、多尾帧或多个音频文件。

> 用户提示文案：**参考音频用于参考音色、节奏或台词，生成结果可能与原音频存在差异。若需要完全保留原声音，应使用后期原音轨合成能力。**

## 4. 模型入参调研

调研原则：产品展示名必须先映射到实际供应商、模型 ID 和接口版本。未取得当前供应商 OpenAPI Schema 或联调结果前，不根据名称相似度推断能力。

| 产品展示模型 | 已核验的公开接口 | 首帧 | 尾帧 | 本地 MP3 参考 | 三者同时使用 | 产品处理建议 |
|---|---|---:|---:|---:|---:|---|
| Seedance 2.5 | 暂未找到可核验的官方公开模型 ID / 入参文档 | 待确认 | 待确认 | 待确认 | 待确认 | 上线前要求供应商提供模型 ID、Schema 与样例请求；确认前相关入口置灰，不继承 Seedance 2.0 配置 |
| Seedance 2.0 | BytePlus `dreamina-seedance-2-0-260128`；Replicate `bytedance/seedance-2.0` | 支持 | 支持，且必须同时提供首帧 | 支持，最多 3 个、总时长不超过 15 秒；音频不能作为唯一参考素材 | **不支持严格首尾帧与参考音频同时使用**；严格首/尾帧、单首帧、多模态参考为互斥场景 | 本期仅开放 1 个 MP3；选择严格首/尾帧后禁用参考音频。若使用 MP3，则视觉图片按“参考图”提交，不承诺严格首帧 |
| Wan 3.0 | 阿里云当前公开模型列表仅核验到 Wan 2.7，未找到 `wan3.0-*` 正式模型 ID | 待确认 | 待确认 | 待确认 | 待确认 | 必须确认产品别名实际映射。若实际映射为 `wan2.7-i2v-2026-04-25`，则首帧、尾帧、驱动音频可同时提交 |
| HappyHorse 1.1 | 阿里云 `happyhorse-1.1-i2v`；Replicate `alibaba/happyhorse-1.1` | 支持 1 张 | 不支持 | 不支持自定义参考音频；模型可自动生成音频 | 不支持 | 仅开放首帧；尾帧和参考音频置灰并提示“当前模型暂不支持” |

### 4.1 关键技术结论

1. **Seedance 2.0**
   - 官方 API 支持首帧、首尾帧、多模态参考（图片、视频、音频）。
   - 首帧、首尾帧、多模态参考是三个互斥生成场景。
   - 参考音频最多 3 个且总时长不超过 15 秒；音频不能单独与文本使用，至少还需一张参考图或一个参考视频。
   - 首尾帧模式可以开启模型自动生成音频，但这不等于上传 MP3 作为参考音频。

2. **Wan 3.0**
   - 截至本次调研，阿里云公开模型清单和 API 文档只核验到 Wan 2.7，不能据此认定产品中的 Wan 3.0 就是 Wan 2.7。
   - 已公开的 `wan2.7-i2v-2026-04-25` 支持 `first_frame + last_frame + driving_audio`，因此只有在供应商确认 Wan 3.0 实际映射和入参兼容后，才能开放三者同时使用。

3. **HappyHorse 1.1**
   - `happyhorse-1.1-i2v` 只接受一个 `first_frame`。
   - 模型输出可以有声音，但公开接口没有自定义参考音频或尾帧入参；需要自定义音频时，阿里云官方建议改用 Wan 2.7。

4. **Seedance 2.5**
   - 当前公开官方模型列表中未核验到该名称对应的正式 API ID；第三方页面的能力描述不能直接作为产品验收依据。
   - 必须由后端接入方提供真实模型 ID、接口地址、Schema、区域、计费和一组成功请求后再更新能力表。

## 5. 产品方案

### 5.1 页面结构

在创意生成输入区增加“参考素材”区域，保持紧凑，不展开大表单：

| 控件 | 默认状态 | 选择后展示 |
|---|---|---|
| 首帧 | 图片占位按钮，文案“首帧” | 64×64 缩略图、文件名提示、替换、删除 |
| 尾帧 | 无首帧时禁用，文案“尾帧” | 64×64 缩略图、文件名提示、替换、删除 |
| 参考音频 | 音频占位按钮，文案“参考音频” | 音频图标、文件名、时长、替换、删除 |

交互规则：

- 控件可用性由当前模型能力配置驱动。
- 不支持时保留控件位置但置灰，悬停/点击提示具体原因，避免切换模型后页面布局跳动。
- 尾帧在未选择首帧时提示：`请先添加首帧图片`。
- 模型支持能力但当前素材组合冲突时提示冲突原因，而不是笼统提示“参数错误”。
- 已上传素材在用户明确删除前保留在本地草稿中。

### 5.2 模型切换

用户切换模型后，系统先做兼容性预检：

- 所有素材兼容：直接切换并保留。
- 存在不兼容素材：弹出确认框，列出将无法用于生成的素材。
  - `取消切换`：返回原模型，素材不变。
  - `继续切换`：保留素材文件在页面草稿中，但标记为“不参与本次生成”；提交前必须删除或切回兼容模型。
- 禁止静默删除素材，也禁止静默忽略并直接扣费生成。

### 5.3 Seedance 2.0 组合处理

Seedance 2.0 需要在两种模式间明确选择：

| 当前素材 | 提交模式 | 约束 |
|---|---|---|
| 首帧 | 严格首帧模式 | MP3 参考不可用 |
| 首帧 + 尾帧 | 严格首尾帧模式 | MP3 参考不可用；尾帧比例按首帧适配 |
| 参考图 + MP3 | 多模态参考模式 | 图片仅作为参考图，不承诺成为视频第一帧 |

当用户已选择严格首帧或首尾帧，再点击“参考音频”时，提示：

> Seedance 2.0 的严格首/尾帧与参考音频不能同时使用。删除首/尾帧后，可将图片作为普通参考图并添加音频。

### 5.4 上传校验

#### 图片

- 数量：首帧 1 张、尾帧 1 张。
- 格式：JPG、JPEG、PNG、WebP。
- 单张大小：不超过 20 MB。
- 宽、高：均不小于 300 px。
- 宽高比：0.4～2.5。
- 尾帧比例与首帧不一致时，上传成功后展示警告：`尾帧将按首帧比例裁切，可能影响画面内容`。

#### 音频

- 数量：1 个。
- 格式：仅 MP3；同时校验扩展名与 MIME，不只校验文件名。
- 大小：不超过 15 MB。
- 时长：2～15 秒。
- 超限时阻止提交并提示重新选择；本期不提供在线裁剪。

> 上述规则是覆盖当前已核验模型的产品层统一限制；后端仍需按实际供应商模型做二次校验。

### 5.5 上传与生成状态

- `未选择`：显示占位按钮。
- `上传中`：显示进度，生成按钮禁用。
- `上传成功`：显示缩略图或音频信息。
- `校验失败`：显示明确原因，允许重新选择。
- `上传失败`：支持重试；不得创建视频任务。
- `素材过期`：提交前重新签名；失败时要求重新上传。
- `生成中`：任务详情保存本次首帧、尾帧、音频快照，便于历史任务复现。

## 6. 用户流程

1. 用户进入“创意生成”，任务类型选择“视频生成”。
2. 用户选择模型。
3. 页面根据模型能力显示首帧、尾帧和参考音频的可用状态。
4. 用户从本地添加素材；前端立即校验格式、大小、尺寸和时长。
5. 素材上传到业务对象存储，获得稳定的 `assetId` 与受控访问地址。
6. 提交前执行组合预检，确认模型、素材、比例、时长均兼容。
7. 后端根据模型适配器将统一字段转换成供应商入参，创建异步生成任务。
8. 任务详情与历史记录展示本次实际使用的参考素材及模型版本。

## 7. 接口与数据要求

### 7.1 前端到业务后端的统一结构

```json
{
  "modelKey": "seedance-2.0",
  "prompt": "产品广告描述",
  "referenceMode": "first_last_frame",
  "references": {
    "firstFrameAssetId": "asset_img_001",
    "lastFrameAssetId": "asset_img_002",
    "audioAssetId": null
  },
  "video": {
    "resolution": "720p",
    "ratio": "9:16",
    "duration": 10
  }
}
```

`referenceMode` 枚举：

- `none`
- `first_frame`
- `first_last_frame`
- `multimodal_reference`

### 7.2 模型能力配置

前后端共用同一份服务端能力配置，前端不得只按展示名称硬编码：

```json
{
  "modelKey": "seedance-2.0",
  "provider": "byteplus",
  "providerModelId": "dreamina-seedance-2-0-260128",
  "supportsFirstFrame": true,
  "supportsLastFrame": true,
  "supportsReferenceAudio": true,
  "supportsFramesWithReferenceAudio": false,
  "requiresFirstFrameForLastFrame": true,
  "audioRequiresVisualReference": true,
  "maxReferenceAudioCount": 1,
  "maxReferenceAudioSeconds": 15
}
```

### 7.3 供应商映射

- Seedance 2.0 严格首尾帧：图片角色映射为 `first_frame`、`last_frame`。
- Seedance 2.0 多模态参考：图片映射为 `reference_image`，MP3 映射为 `reference_audio`；不与严格帧角色混用。
- HappyHorse 1.1：首帧映射为 `media[{ type: "first_frame" }]`。
- Wan 3.0：取得真实 Schema 前不得建立正式映射；若供应商确认映射至 Wan 2.7，则映射为 `first_frame`、`last_frame`、`driving_audio`。

本地文件必须先上传到业务对象存储，再将 URL 或供应商要求的资产 ID 传给模型。生成记录保存业务 `assetId`，不长期依赖供应商临时 URL。

## 8. 提示与错误文案

| 场景 | 文案 |
|---|---|
| 模型不支持尾帧 | 当前模型暂不支持尾帧，请切换模型 |
| 模型不支持参考音频 | 当前模型暂不支持自定义参考音频 |
| 未选首帧选择尾帧 | 请先添加首帧图片 |
| 首尾帧与音频冲突 | 当前模型不能同时使用严格首/尾帧和参考音频 |
| 图片格式错误 | 请选择 JPG、JPEG、PNG 或 WebP 图片 |
| 图片尺寸不足 | 图片宽高均需不小于 300 px |
| 图片过大 | 单张图片不能超过 20 MB |
| 音频格式错误 | 请选择 MP3 文件 |
| 音频时长超限 | 参考音频需为 2～15 秒 |
| 能力未完成接入 | 该模型的参考素材能力正在确认中，暂不可用 |

## 9. 埋点

| 事件 | 关键属性 |
|---|---|
| `video_reference_upload_click` | modelKey、referenceType |
| `video_reference_upload_result` | modelKey、referenceType、success、errorCode |
| `video_model_switch_conflict` | fromModel、toModel、conflictTypes |
| `video_generate_precheck_failed` | modelKey、reason |
| `video_generate_submitted` | modelKey、referenceMode、hasFirstFrame、hasLastFrame、hasAudio |
| `video_generate_result` | modelKey、referenceMode、success、providerErrorCode、latency |

不得在埋点中上传原始图片、音频 URL、文件名、提示词或其他用户内容。

## 10. 验收标准

### P0

1. 用户可从本地分别选择 1 张首帧和 1 张尾帧图片，并可替换、删除。
2. 用户可从本地选择 1 个 MP3，并看到文件名与时长。
3. 尾帧未选择首帧时不可用；所有文件校验失败时不得创建生成任务。
4. 模型切换后，入口状态与服务端能力配置一致，不兼容素材不会被静默删除或静默忽略。
5. Seedance 2.0：
   - 首帧与首尾帧任务可正确提交；
   - 参考图 + MP3 可正确提交；
   - 严格首/尾帧与 MP3 同时选择会在扣费前被阻止。
6. HappyHorse 1.1：只开放首帧，尾帧与 MP3 明确置灰。
7. Seedance 2.5、Wan 3.0：未配置真实模型 ID 与能力前，相关功能保持关闭；配置完成后以联调用例为准开放。
8. 历史任务能展示当次实际使用的模型 ID、首帧、尾帧和参考音频快照。
9. 后端对 MIME、大小、尺寸、时长和素材组合做二次校验，不能依赖前端校验。

### 上线前模型门禁

每个模型必须分别完成以下用例后才能将能力开关设为 `true`：

- 首帧生成成功；
- 首帧 + 尾帧生成成功；
- 视觉参考 + MP3 生成成功；
- 首帧 + 尾帧 + MP3 生成成功或得到明确“不支持”的供应商错误；
- 非法 MIME、超大文件、超时长音频被正确拦截；
- 记录真实供应商模型 ID、请求字段、区域与计费单位。

## 11. 后续版本

- 音频裁剪、波形预览与试听。
- 从资产库选择首帧、尾帧和参考音频。
- 多音频参考及按用途标记“人声 / 音乐 / 音效”。
- 原音轨复用、声音克隆和后期混音能力。
- 根据素材自动推荐兼容模型。

## 12. 待确认事项

1. 产品中的 Seedance 2.5 与 Wan 3.0 分别对应哪个供应商、模型 ID、区域和接口版本？
2. “与之前产品一样的声音”优先指音色、台词、背景音乐、节奏，还是必须完全复用原音轨？
3. 音频参考是否需要默认参与最终视频声音，还是只作为生成条件？
4. 任务失败时，上传素材保留多久；用户能否在重试中继续复用？
5. 供应商是否允许上传包含真人声音或真人肖像的素材，是否需要增加授权确认？
