# 现有达人数据利用评估与首期落地建议

版本：V1.0　日期：2026-09-20

本文为第二份独立文档，以《UGC爆款 需求文档0909》及本轮提供的六张截图为业务背景，说明现有达人数据如何服务原有目标，以及首期可交付的功能、规则和落地步骤。

本文不替代原UGC需求文档。完整的TikTok账号运营、内容搜索与观看策略、地区扩充、长期采集与转存方案，归入第一份《UGC爆款内容供给与运营方案》。本文只说明首期对这些能力的依赖。

> 阅读口径：现有数据情况来自团队描述和截图，尚未完成字段及接口核验；下文“首期建议”是本次产品方案，需通过样本验证后排期。文中的图片位置均为占位。

## 1. 结论与首期定位

**现有达人数据可以辅助实现UGC目标，但不能直接作为合格素材池向客户全量展示。**

其主要价值是筛选小体量账号、发现候选视频、补充作者和互动数据。当前缺少已确认的AI属性、逐条精选结果和可用于站内播放、下载、复刻的视频文件，因此，“已有上亿视频数据”不等于“已有上亿条可用创作素材”。

建议首期采用以下方式：

1. 继续使用已有AI内容推荐账号，作为主要内容发现来源。
2. 从现有达人数据中提取有限候选，验证它能否补充符合目标的AI视频；同时用于补全已发现视频的作者和表现数据。
3. 只审核准备上架的有限候选，合格后进入UGC共享池；不对全库进行视频下载和内容识别。
4. 根据实际验证结果开放查看、收藏、播放、下载和复刻，分别判断各项能力是否可用。
5. 首期暂不建设独立达人广场，避免将素材发现项目转为达人合作项目。

**首期最低交付价值：用户能更快找到经过筛选的小账号AI视频，查看参考并收藏。**

完整的“看懂参考 → 收藏积累 → 复刻创作”还需要验证视频可作为参考输入进入现有创作流程。若首期只能跳转源视频，必须按“精选发现与收藏试点”验收，不能按完整UGC创作闭环验收。

## 2. 与原需求目标的匹配评估

原需求的两个用户目标保持不变：一是寻找粉丝不足1万的账号发布的优质AI视频，用于参考创作；二是让运营人员每天浏览优质内容，积累题材、开头、演示形式和节奏的判断。

【图片占位：原UGC需求文档中的需求背景与需求目标】

| 原目标 | 现有数据能够支持的部分 | 仍缺少的条件 | 判断 |
| --- | --- | --- | --- |
| 找到粉丝不足1万的账号 | 使用粉丝数筛选账号 | 核实数据库是否充分覆盖小账号、粉丝数据是否及时 | 可以支持预选，覆盖率待验证 |
| 找到这些账号发布的AI视频 | 使用标题、hashtag、封面等发现线索 | 逐条确认AI属性及创意价值 | 不能直接判断，需要有限审核 |
| 找到近期值得参考的视频 | 使用单视频发布日期、播放和互动数据排序 | 去除个人动态，确认内容可学习；必要时补充数据 | 可以辅助，不能仅凭高播放入选 |
| 每天浏览并积累创意 | 用精选结果形成每日内容供给 | 稳定的合格供给、查看入口和个人收藏 | 少量精选也能提供部分价值 |
| 一键复刻生成类似素材 | 提供候选视频及源链接 | 可用的参考文件、输入适配及生成结果验证 | 现有数据本身不能保证 |
| 提升WAU和创作转化 | 记录浏览、收藏、回访和创作行为 | 真实客户试用与连续观察 | 是待验证结果，不能由数据规模推导 |

如首期只把达人列表及其最新10条视频搬到产品中，仍需要用户自己判断AI属性和排除个人动态，不能证明减少了寻找目标素材的时间。此方式不建议作为UGC首期交付。

## 3. 现有数据的使用边界

### 3.1 可以复用的数据

团队当前描述的资源包括：每日更新大量TikTok达人账号数据、上亿规模的视频记录，以及每个达人最新10条视频的展示信息。规模、更新范围和可调用字段需由数据团队核实。

【图片占位：现有“找达人”列表、达人详情、近期视频列表三张截图】

| 数据 | 首期用途 | 不应推导出的结论 |
| --- | --- | --- |
| 达人粉丝量、最近发布时间 | 筛选小账号、优先查看仍在更新的账号 | 小账号一定有优质AI内容 |
| 达人地区、语言、行业标签、hashtag | 缩小候选范围，补充检索词 | 达人地区等于该视频受众地区；行业标签等于每条视频的内容 |
| 单视频封面、标题、源链接、发布日期 | 形成候选、人工查看、客户展示 | 封面或标题含“AI”就能确认视频由AI生成 |
| 单视频播放及互动数据 | 提供参考，辅助确定审核优先级 | 高互动等于带货效果好，或等于值得复刻 |
| 达人平均播放、互动率 | 作为账号表现背景 | 可替代该条视频的实际数据 |
| 达人GMV预估、带货客单价、类目、佣金率 | 后续达人合作评估；必要时辅助缩小商业内容范围 | 该视频的GMV、ROI或广告投放效果 |
| 性别、受众画像等 | 后续有明确达人匹配需求时使用 | 作为本次AI素材精选的必要门槛 |

最新10条视频只能代表当前可见样本，不能代表作者全部作品。若其中没有合格内容，首期跳过该账号，不因其GMV或粉丝表现好而放入无关视频，也不默认补采其全部历史作品。

### 3.2 开发前必须核实的字段和能力

| 核实项 | 用途 | 缺失时的处理 |
| --- | --- | --- |
| 稳定的视频标识、作者标识及源链接 | 去重、关联作者、收藏、跳转 | 无法确认同一视频或源链接无效时，不发布 |
| 当前粉丝数及数据更新时间 | 判断是否符合“小账号”目标 | 待补充，不按小账号精选发布 |
| 单视频发布日期、时长 | 判断近期程度及5–120秒要求 | 由运营查看源视频补齐；无法确认则待补充 |
| 地区、语言的具体含义 | 判断是否符合首期美区内容方向 | 地区未知不自动当作美区；必要时人工核实 |
| 单视频播放、点赞、评论、收藏、分享分别是否可取 | 正确展示素材表现 | 缺失项显示“—”或隐藏，不补为0，不用达人均值替代 |
| 视频级商品关联、广告标识、AI标识是否实际可用 | 提高候选命中率 | 不将截图中的标签视为已具备接口能力；缺失时用人工审核 |
| 封面和视频能否稳定展示，允许使用的范围 | 决定站内展示和下载范围 | 分别验证；只有链接时只提供封面信息及源视频入口 |
| 已有创作流程接受哪种参考输入 | 决定能否直接进入复刻 | 链接、文件分别测试；不能自动带入时不显示“一键复刻” |

数据团队不必先补齐所有达人画像。首期优先补齐视频身份、源链接、粉丝数、发布日期、时长和实际可用的展示字段。

## 4. 首期内容供给与处理规则

### 4.1 两个来源进入同一候选流程

**来源A：已有AI推荐账号。** 运营从当前已能持续发现AI内容的账号中选取候选，保留源链接，再补充作者、发布时间和视频数据。

**来源B：现有达人数据。** 先利用已有字段缩小到目标地区、粉丝不足1万、近期有发布的账号，再从其最新10条视频中寻找AI相关线索。只提取计划审核的候选，不将所有命中视频直接上架。

统一流程为：

**发现候选 → 去重与基础检查 → 人工确认内容 → 补齐必要信息 → 验证可用操作 → 发布到共享池。**

【图片占位：首期两类来源进入候选、审核、发布和用户使用的流程图】

来源A、B使用相同入选标准，分别记录合格数量与审核耗时。现有达人数据只有在能带来新增合格素材，或确实减少信息补全工作时，才值得继续扩大投入。

### 4.2 候选与入选条件

以下是本次首期建议。时长、美区、小账号方向沿用已有要求；近30天发布优先是待样本验证的预选口径，不能与共享池的近7天展示窗口混为一谈。

| 条件 | 候选预选 | 正式入选要求 |
| --- | --- | --- |
| 视频时长 | 5–120秒，包含边界值 | 必须确认；不符合则不进入本次精选 |
| 地区和语言 | 首期美区方向，优先运营可审核的语言 | 确认符合目标市场的内容语境；仅有作者地区不能证明受众地区 |
| 作者规模 | 粉丝数小于10,000，不能用“小于等于”替代 | 入选时核实并留存粉丝数及核实时间 |
| 发布时间 | 优先近30天发布的视频 | 保留真实发布日期；更早的有价值内容仅作为人工补充，并说明原因 |
| AI相关性 | 标题、标签、封面、已知AI创作者作为线索 | 运营结合完整视频和作者说明确认；证据不足进入待补充，不强行标为AI |
| 学习价值 | 有明确的题材、开头、演示、视觉表达或节奏亮点 | 至少写明一句“值得参考什么”，不能只写“播放量高” |
| 内容表现 | 在有限候选内参考播放和互动数据安排审核顺序 | 由运营结合发布时间、账号体量和内容判断，不设全类目统一“爆款线” |
| 可访问性 | 有封面信息和源链接 | 审核时能查看完整内容；是否能站内播放另行验证 |
| 重复情况 | 对已选候选及已发布池检查 | 同一视频保留一条；同内容轻微改版可标记重复并不发布 |

粉丝数限制用于本期主精选池的入选判断。作者入选后涨粉超过1万，不自动删除历史精选和用户收藏；前台展示最近可用的粉丝数据，不持续宣称其当前仍不足1万。

### 4.3 哪些内容留下，哪些内容排除

沿用原文档“具有可学习价值的AI相关视频”的定位，不把全部内容改成必须有商品链接的带货广告。首期收录AI商品演示，以及能明确迁移到商品表达的视觉创意、拟人角色或情节表达。

对此前提出的“过滤非带货短剧”，首期具体落为：**纯娱乐、连续追剧情、缺少商品表达或可迁移创意价值的非带货短剧不进入主精选池。** 对有商品关联的AI剧情，仍需逐条审核。

| 审核项 | 处理规则 |
| --- | --- |
| 个人生活动态、聊天、旅行记录等 | 与本次AI创意参考无关的排除，不能因作者有带货数据而保留 |
| 普通真人内容 | 本期小账号AI精选不收录；不因其热门而混入 |
| 涉黄、暴力血腥、仇恨、政治宣传或争议等 | 按产品内容审核口径排除；审核结果不确定时不发布 |
| 纯搬运、重复视频、无内容拼接 | 排除；相同创意并不自动认定为同一视频 |
| 黑屏、明显损坏、画质或声音影响理解 | 退回补充或排除，保证用户能够看懂参考 |
| 夸张功效、危险示范等不适宜模仿内容 | 排除或交由复核，不能仅以高互动为由通过 |
| 无法确认AI属性、时长或完整内容 | 标为待补充，补齐后重新审核 |

首期不默认要求运营识别所有生成工具或还原完整提示词，也不承诺“已精选”就代表可任意下载、再发布或复刻作者身份。

### 4.4 如何控制审核成本

不新增对上亿视频逐条做内容理解的任务。数据团队现有的日常数据更新继续运行，产品侧仅对缩小范围后的有限候选做检查。

建议第一轮最多比较100条去重候选：来源A、B各最多50条，不足按实际数量记录。该数量用于验证，不是每日采集承诺。运营记录审核时长、合格数、退回原因，以及来源B相对来源A的新增合格数。

后续每日候选上限由实际产能确定：

> 每日可审核量 ≈ 当日可投入审核分钟数 ÷ 实测每条平均审核分钟数。

达到当日审核上限后，剩余候选顺延；未经审核的内容不能为了补足数量而上线。近7天仍有合格历史内容时，继续按原分发规则提供；全部看完后展示终点。

原文档“每日采集300条”保留为整体供给方案的候选目标，不等于每日必须审核通过或展示300条。本次首期先测合格产出与成本，再确定每日发布量。

### 4.5 时间、审核状态与发布

夜间采集以**北京时间06:00前完成**为要求，替代截图中的08:00采集截止口径。对既有达人数据，必须核实上游实际更新时间；若当天数据06:00前尚未产出，只能使用最近一次可用快照并保留其时间，不能标为已完成当日更新。

06:00是采集截止时间，不代表未经审核的视频自动发布。首期运营审核完成后发布，供给不足时保留合格历史内容。固定的每日精选发布时间由运营排班确认后写入第一份方案。

| 状态 | 含义及后续处理 |
| --- | --- |
| 待审核 | 已取得候选基础信息，等待查看完整视频 |
| 待补充 | 缺少必要字段、完整视频暂时无法访问或判断证据不足；补齐后返回待审核 |
| 不通过 | 确认不符合入选条件，记录原因，不对客户展示 |
| 已通过 | 内容审核通过，但尚未发布；确认展示信息和可用操作 |
| 已发布 | 用户可在共享池中浏览；能力变化时同步调整操作入口 |
| 已下线 | 已确认不适合继续分发；停止进入新队列，收藏按失效规则处理 |

发布前再检查源链接、关键信息和可用操作，构成首期的二次校验。若后续取得文件，需要再核对文件是否为同一视频、是否完整及是否通过审核；不能把通过文字或封面检查等同于文件审核通过。

首期不做全量视频转存。有明确需求且已确认可使用的少量入选视频，才进入文件获取及复刻验证。单次访问失败先作为异常处理，不直接认定视频已删除或下线。

## 5. 首期产品功能与用户行为

### 5.1 保持原产品入口，按能力交付

继续使用“发现 → UGC爆款”和“资产 → 我的收藏”。不新增与其重复的素材广场，也不在本期新增达人广场菜单。

原文档的大视频连续浏览、下载和一键复刻作为完整目标保留。首期是否开放每项操作，由该条素材实际具备的能力决定，不能以“已发布”统一判断。

| 功能 | 首期要求 | 边界 |
| --- | --- | --- |
| 精选展示 | 展示已经审核并发布的素材信息 | 未审核候选、达人最新10条视频不能自动进入前台 |
| 查看源视频 | 使用有效源链接在新浏览器标签页打开，保留当前浏览位置 | 外跳成功不记为站内播放或视频看完 |
| 收藏与取消收藏 | UGC与我的收藏共用同一收藏状态 | 收藏的是该条素材，不是自动收藏作者 |
| 素材详情 | 查看标题、作者、粉丝数、发布日期及可用互动数据 | 没有视频文件时使用封面信息，不放置不可用的假播放器 |
| 站内播放 | 有稳定可用的视频展示方式且验证通过后开放 | 只有封面或源链接不代表具备播放能力 |
| 下载 | 该素材确有可用且允许提供的文件时开放 | 不将源网页链接伪装成视频文件下载 |
| 一键复刻 | 能把该条素材作为正确参考自动带入现有创作流程后开放 | 只有源链接且流程不支持时隐藏入口；手工补传不能称为一键复刻 |

只有链接的首期版本仍可验证精选与收藏价值，但无法完整实现原需求中的沉浸刷视频体验。如不能提供比直接刷TikTok更好的筛选结果，不应继续扩展展示功能。

### 5.2 UGC展示规则

【图片占位：原UGC页面——文案收起状态与展开状态】

1. 素材展示视频标题、封面或可播放视频、作者头像与名称、粉丝数、原始发布日期，以及实际取得的单视频互动数据。卡片与详情使用同一份素材信息。
2. 标题默认显示1–2行，超出显示“更多”，展开后可“更少”收起；切换到另一条素材时恢复收起状态。
3. 站内可播放的素材沿用现有布局：作者及数据在右侧上方，分隔线区分作者和视频数据，操作按钮在下方。顶部不恢复已删除的筛选栏、搜索框和刷新按钮。
4. 产品收藏按钮使用与“我的收藏”一致的书签图标；源视频收藏量使用五角星图标。产品内的收藏行为不改写源视频收藏量。
5. 缺少互动指标时显示“—”或不展示该项，不显示0，不使用达人均值、GMV等替代。
6. 仅有链接的素材明确展示“查看源视频”；若进入详情，说明站内暂不支持播放。该状态与“原来可用、现在失效”区分。
7. 查看作者可通过作者区域进入有效的作者源主页，不新增独立“查看作者”操作按钮。

数据更新时间需留存供运营判断新鲜度，本期不恢复已删除的播放器右下角“数据更新时间”。所有“原视频”文案统一为“源视频”。

### 5.3 分发与浏览记录

保留原文档的分发逻辑：今日入池未看内容 → 昨日入池未看内容 → 近7天其他未看内容。今日和近7天按北京时间及**首次发布到共享池的日期**计算，前台发布日期仍展示视频在TikTok的原始发布时间。

- 近7天包含今天及前6个自然日，各层不重复；更新视频指标不会将旧素材重新算作今日新内容。
- 不同用户可看到相同素材，各自保存浏览记录和随机队列；某用户浏览后不移除公共素材。
- 可播放素材仍按原要求，在成功展示并开始播放后记为已展示；预加载和加载失败不计入。
- 仅有链接的版本单独记录“卡片已展示”和“源视频点击”：卡片成为当前内容且封面信息加载成功才记展示，不能套用“已播放”统计。该差异只适用于链接试点。
- 主动上翻、打开收藏和重看允许重复；页面刷新不重新采集、不清空记录、不重排已有剩余队列。
- 全部可分发内容浏览完后提示“近7天精选已看完，稍后再来看看”，并提供进入我的收藏的入口。

### 5.4 我的收藏与详情弹窗

【图片占位：原“我的收藏”列表与素材详情弹窗】

1. 入口为“资产 → 我的收藏”。默认按最近收藏倒序，支持搜索标题或作者及分页；不增加顶部空白栏、条数、“最近收藏”切换控件或收藏时间展示。
2. 卡片中作者头像、名称、粉丝数放一行；播放量、发布日期放一行。查看按钮统一使用“查看”。
3. 点击封面或“查看”，在当前页面打开素材详情弹窗。关闭后回到原列表位置，保留搜索词和页码。
4. 可播放素材显示播放器；仅链接素材显示封面及源视频入口。长标题展开逻辑与UGC页面一致。
5. 同一用户对同一视频只保留一条收藏。UGC和弹窗中收藏成功后同步状态；重复点击或跨日再次入池不新增收藏记录。
6. 取消收藏移除个人收藏关系，两个页面同步更新；不删除公共素材、其他用户收藏或已创建项目。若当前分页因此为空，回到最近的有效页。
7. 超过7天的收藏继续保留。源视频确认删除或不可访问时，保留标题、封面等已有信息并标记状态；分别判断站内文件、下载和复刻是否仍可用，不能假定全部同时失效。
8. 无收藏显示“还没有收藏，去UGC爆款发现灵感”；搜索无结果显示“没有找到相关收藏”并提供清空搜索。

### 5.5 进入创作的验收边界

已验证可用于复刻的素材，点击“一键复刻”后带入正确的参考视频；用户补充商品和必要输入，再提交生成，能够看到新项目及生成结果。收藏状态不影响已经创建的项目。

若只能让用户自行获取文件再上传，说明这属于现有上传创作流程的人工衔接，首期可用于小范围验证参考价值，但不能算一键复刻功能交付。

原目标中的“发布到TikTok账号”属于创作后的使用结果。本期不新增发帖功能；若已有发布能力，可在验证通过后衔接，否则用户通过现有导出及手动发布流程完成。

## 6. 达人广场的评估与建议

**本期暂缓独立达人广场。** 现有数据适合支持找达人，但用户当前要完成的是“找到AI创意并进入创作”。找到创作者、查看其画像，不能替代素材精选，也不能单独完成达人合作。

首期保留素材作者信息及源主页入口即可，先观察客户是否持续提出“想找这个作者合作”的需求。

若后续确认存在独立的达人合作需求，最小业务流程应包含：

**筛选达人 → 判断与商品的匹配度 → 加入合作候选 → 查看有效联系渠道 → 记录联系和合作进度 → 回收交付素材。**

届时优先评估复用已有候选名单、CRM或合作记录能力。是否能复用需核实，截图展示的功能不能直接视为本产品已接入。本期不建设联系消息、自动邀约、报价、寄样和合作管理模块。

如果没有持续的合作需求、有效联系渠道或后续承接流程，新增达人广场只会形成“看完达人后无处继续”的浏览功能，不建议上线。

## 7. 验收与效果验证

### 7.1 首期功能验收

| 编号 | 场景 | 必须得到的结果 |
| --- | --- | --- |
| B01 | 从现有数据提取候选 | 仅处理约定的有限候选；未开启全库内容识别或下载任务 |
| B02 | 发布小账号AI精选 | 粉丝数、AI判断、时长、源链接和参考价值均有审核记录；不确定项未混入发布结果 |
| B03 | 普通动态命中达人筛选 | 即使达人有GMV或行业标签，无关视频也不能直接发布 |
| B04 | 同视频重复进入 | 共享池和个人收藏不新增重复视频；更新指标不重置首次入池日期 |
| B05 | 缺少某项数据 | 缺失不显示为0，不用达人维度数据替代单视频数据 |
| B06 | 只有源链接 | 提供正确封面信息和源视频入口；无假播放器、不可用下载或虚假的一键复刻 |
| B07 | 收藏、取消、搜索、分页 | 列表及详情状态一致；取消不影响共享素材、他人收藏和已创建项目 |
| B08 | 今日内容看完 | 继续进入昨日及近7天其余内容；去重有效，全部看完有终点提示 |
| B09 | 视频超过共享池7天窗口 | 不再进入默认新队列，已有收藏仍保留 |
| B10 | 暂时加载失败或确认失效 | 能区分临时异常与已确认不可用，不因一次失败删除收藏 |
| B11 | 站内播放、下载、复刻开放 | 每项分别验证；复刻需正确带入参考、提交并产出结果，不能仅验证按钮跳转 |

B11按实际开放功能验收。未开放能力应在版本交付清单中明确列出，不能将整项标为通过。

### 7.2 试点需要回答的问题

| 问题 | 记录方式 | 用于决定什么 |
| --- | --- | --- |
| 数据库是否覆盖目标小账号？ | 查询范围内小于1万粉丝且有近期视频的账号数；检查缺失情况 | 是否值得继续从该数据源取候选 |
| 哪个来源更容易找到合格素材？ | 各来源合格数÷实际审核数，并记录具体淘汰原因 | 来源A、B的投入比例 |
| 审核成本是否可接受？ | 实际审核分钟数÷合格素材数；补字段耗时单独记录 | 每日供给量及是否需要补充识别能力 |
| 既有数据是否提供新增价值？ | 来源B中相对来源A不重复的合格素材数、信息补全耗时变化 | 是否扩大接入，而非只看总数据规模 |
| 用户是否更快找到有用参考？ | 与原工作方式比较找到一条愿意收藏或用于创作的素材所需时间，并记录反馈 | 精选服务是否值得继续 |
| 用户是否持续使用？ | 试点用户的有效周活、跨日回访、收藏和收藏回访 | 是否产生稳定回访理由 |
| 用户是否进入创作？ | 素材详情用户中实际提交创作的用户比例；另记成功生成数 | 是否实现了原目标中的创作转化 |

“有效周活”在本次试点中建议定义为：一周内至少完成一次素材播放、源视频点击、收藏或创作提交的去重用户。仅打开页面、预加载卡片不算有效使用。

源视频点击不能证明用户看完视频；复刻按钮点击不能证明已提交创作。链接版本的创作转化应标为尚未验证，而不是宣称已实现闭环。小规模试点用于判断方向，不直接归因整个平台WAU增长。

## 9. 底部落地计划

以下按依赖顺序执行。时间为建议验证节奏，研发交付日期在能力核验后估算。

| 步骤 | 主要工作 | 交付结果 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 1. 核实数据和能力，建议1–2个工作日 | 检查小账号覆盖、最新10条字段、更新时间；分别测试源链接、播放、下载、复刻 | 数据能力表、缺失字段表、真实可用样本 | 能取到目标候选并查看完整内容；明确哪些操作可以交付 |
| 2. 做小批精选验证，建议2–3个工作日 | 两个来源各最多50条候选，人工审核并记录时间和原因 | 首批合格素材、来源合格率、每条合格素材成本 | 产生客户愿意参考的AI内容；能说明现有数据提供了多少新增价值 |
| 3. 确定首期版本并接入 | 复用UGC和我的收藏入口，接入已审核内容及实际可用操作 | 可供客户使用的精选与收藏版本；若能力具备则同时开放播放和复刻 | 通过B01–B11中本版本适用项，交付范围明确 |
| 4. 小范围客户试用，建议连续2周 | 持续精选，观察找参考时间、有效使用、收藏回访及创作行为 | 试点记录、内容反馈、投入产出评估 | 确认用户价值后扩大供给；否则调整内容方向或暂停扩展 |
| 5. 决定后续投入 | 判断补媒体能力、扩大现有数据来源，还是继续以原推荐账号为主 | 下一阶段明确范围与优先级 | 每项投入能对应已验证的瓶颈 |

后续决策按以下结果执行：

- **现有达人数据有合格内容且提供明显增量：** 扩大有限候选范围，继续保持先预选、后审核。
- **现有达人数据难以找到目标AI内容：** 保留其作者及指标补全价值，以已有推荐账号继续供给，不为使用存量数据而改变产品目标。
- **客户认可精选，但站内播放或复刻受阻：** 优先补齐少量入选素材的媒体和参考输入能力，验证完整创作流程。
- **客户只外跳、很少收藏或回访，也没有节省寻找时间：** 先调整精选标准和内容价值，不新增达人广场或扩地区来掩盖问题。
- **不能进行有限审核，也无法确认AI属性和参考价值：** 不直接向客户上线原始达人视频流；先完成小批人工选材试验。

**本次首期推荐范围：有限候选选取、人工审核发布、精选查看、个人收藏、源视频入口，以及真实可用的作者和互动数据。播放、下载和一键复刻在分别验证通过后纳入交付。达人广场暂缓。**
