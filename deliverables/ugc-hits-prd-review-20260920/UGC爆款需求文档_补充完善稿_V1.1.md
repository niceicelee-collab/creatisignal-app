## 1. 需求背景

Face pitch客户提出两个需求：

1. 找到粉丝不足1万的账号发布的AI视频，参考其创意并生成类似的AI素材，发布到TikTok账号。
2. 让运营人员每天浏览优质热门视频，积累对题材、开头、演示形式和节奏的判断。

当前已有一个经过日常使用、持续获得高互动AI视频推荐的TikTok账号，可作为首版内容发现入口及推荐素材来源。

本功能将该类推荐内容整理成每日更新、经过审核、可以观看并进入创作的内容池，并逐步建立备用账号和稳定供给流程，降低单账号异常造成内容中断的影响。

## 2. 需求目标

| 目标 | 具体说明 |
| --- | --- |
| 用户价值 | 减少寻找小体量账号优质AI视频的时间，完成“看懂参考 → 收藏积累 → 复刻创作”，形成每日回访理由 |
| 产品目标 | 提升平台WAU及有效活跃，提高从灵感发现到实际提交创作的转化 |
| 内容供给目标 | 每日从运营账号的TikTok推荐流中采集候选，审核后形成稳定、可用的共享内容池 |
| 运行目标 | 采集、转存、审核和发布状态清楚；账号或任务异常不会将未审核内容直接暴露给用户 |

验收时分别判断“供给链路是否正常”和“用户是否使用”。采集了多少视频不能替代收藏、回访或创作转化；点击复刻按钮也不能替代实际提交创作。

## 3. 核心场景与主链路

### 3.1 用户场景

**场景1：找到好的创意。** 电商运营人员打开UGC爆款，默认查看系统精选AI视频，可以不断下刷。通过视频内容、播放和互动表现、账号粉丝数及发布日期，判断创意是否适合自己的商品；发现值得参考的视频后收藏或点击一键复刻。

**场景2：每天刷刷积累网感。** 运营人员每天查看新视频、连续浏览、收藏有用创意，也可以回看近7天精选及个人收藏。

**场景3：从收藏回到创作。** 用户进入“资产 → 我的收藏”，找到此前收藏的视频，在详情弹窗中再次观看和查看数据，进行下载或一键复刻。

### 3.2 用户核心链路

发现 → UGC爆款 → 沉浸刷视频 → 查看内容与数据 → 收藏至我的收藏／下载／一键复刻。

### 3.3 内容运营链路

运营账号养号与维护 → 浏览目标内容、改善推荐相关性 → 夜间采集推荐视频 → 基础检查 → 转存 → 二次审核 → 发布到共享池 → 用户浏览及创作 → 依据供给质量和用户反馈调整内容方向。

TikTok运营账号与产品用户账号是两个概念：前者用于发现和采集内容，后者拥有独立浏览记录及收藏。产品用户操作不直接同步为TikTok账号的点赞或收藏。

## 4. 什么是UGC爆款

收录TikTok公开发布、具有可学习价值的AI相关视频。它是来自有限推荐来源的运营精选集合，不代表覆盖TikTok全站，也不宣称是平台官方榜单。

可包含产品演示、AI剧情、视觉创意、拟人角色等，**不要求全部为带货视频**。判断重点是AI相关性、创意是否值得学习，以及用户能否借鉴其题材、开头、表现形式或节奏。

首期主精选池以**入选时作者粉丝数小于10,000**为必要条件。粉丝数等于10,000不符合“不足1万”。养号时可以参考大账号的优质AI内容，但不因此放宽入选条件。作者入选后涨粉超过1万，不删除已入池内容或用户收藏，前台按最新可用数据展示。

“非带货”不单独作为排除理由。应排除与本目标无关的普通真人短剧、剧情搬运和生活动态；有学习价值的AI剧情按照同一精选标准审核。

## 5. 用户如何使用

UGC爆款默认进入“刷灵感”：大视频、上下切换、标题展开与收起、收藏、下载和一键复刻。

首版沿用已确认的简化页面，不恢复顶部筛选栏、搜索框或刷新按钮。“我的收藏”保留标题／作者搜索。

所有正式分发的视频都应已经完成转存、播放校验及审核。本版本不以只展示封面、跳转源视频的列表替代原有沉浸式播放需求；未准备好的素材继续留在处理或待审核状态。

### 6.2 TikTok养号策略

这里的“养号”指持续维护与目标内容匹配的推荐偏好和账号可用性。养号完成不以账号注册天数或累计操作次数判定，而以推荐内容质量和可采集状态判定。

**账号配置与分工**

| 账号 | 职责 | 初期安排 |
| --- | --- | --- |
| 主账号 | 稳定发现并提供美区AI推荐素材 | 使用当前已有账号，先评估现有推荐质量，不清空已有偏好重新开始 |
| 备用账号 | 保持相同内容方向，处理主账号临时不可用或供给不足 | 建议新增1个，由同一内容标准维护；达标后才计入有效备用 |
| 新地区账号 | 为后续新增市场建立独立内容方向 | 扩区时再准备，不提前建立大量账号 |

每个账号记录：内部名称、目标市场、主要语言、内容方向、负责人、备用负责人、当前状态、最近成功访问时间、最近成功采集时间及推荐相关率。登录凭据不记录在普通任务日志或产品用户页面中。

首期账号状态分为“培养中、可采集、异常、暂停”。只有“可采集”账号进入当晚任务；异常账号恢复访问并确认推荐方向后再恢复任务。

**稳定性保障**

- 为账号安排固定负责人、常用设备和稳定访问环境，避免多人同时操作同一账号。账号不与个人娱乐浏览混用。
- 完成可恢复的邮箱／手机号绑定、双重验证及可信设备检查，交接时确认恢复方式可用。TikTok官方账号安全指引支持这些做法。[账号安全说明](https://support.tiktok.com/en/safety-hc/account-and-user-safety/account-safety)
- 养号操作和采集任务错开时间，同一账号不同时进行人工浏览与后台采集。
- 验证码、登录失效、访问受限或账号处罚触发暂停及人工处理；不把不断重试或更换账号规避限制作为稳定性方案。
- 主账号临时不可用时，仅在备用账号状态正常、方向一致且允许访问的情况下接管；不足的供给由共享池历史合格内容承接。

**培养与维护节奏——建议试运行默认值**

| 阶段 | 操作安排 | 检查结果 |
| --- | --- | --- |
| 新账号第1–3天 | 每日2次，每次15–20分钟；先用目标关键词找到相关样本，再浏览推荐流 | 是否开始稳定出现目标AI内容，记录无关内容类型 |
| 第4–7天 | 保持每日浏览；以推荐流为主，仅在方向不足时补充搜索 | 推荐相关性是否持续改善，而非某一次偶然出现相关视频 |
| 稳定阶段 | 主账号每日1–2次维护，每次约10–20分钟；备用账号每日一次简短检查和相关内容浏览 | 推荐相关率、当日候选数、异常情况 |
| 每周复盘 | 查看近7天推荐相关性、重复率、最终入池量，调整关键词和关注来源 | 保留有效方向，减少无关或重复来源 |

上述天数是观察周期，不承诺养满7天就能达到要求。已有主账号可直接进行质量检查和试采，无需重复培养流程。

建议每个账号每日人工抽查推荐流中连续20条视频。推荐相关率＝其中符合“AI且具有创意学习方向”的视频数÷20；不能先挑选相关视频再计算。此指标不等于最终小账号素材合格率。

建议以连续3天推荐相关率达到60%及以上、访问正常、能完成一次小批试采作为备用账号可采集的初始标准。该阈值用于内部管理，首周根据实测调整。备用账号未达标时如实标记“培养中”，不计为已有供给保障。

### 6.3 TikTok内容策略

**推荐机制与运营建议的边界**

TikTok公开说明，观看或跳过、互动、内容信息和语言等用户信息会影响推荐，搜索也会参考内容与查询的匹配度。因此，本方案使用“有目的的搜索＋真实观看反馈＋推荐流检查”维护内容方向；不把固定停留秒数或某个操作时段当作确定的推荐算法规则。[TikTok推荐机制说明](https://support.tiktok.com/en/using-tiktok/exploring-videos/how-tiktok-recommends-content)

**内容方向与关键词**

下表是首期种子词，用于查找样本和改善推荐方向，不代表实时热门标签排名。每次选择2–3组与当前内容目标相关的词，不需要把全部词逐一搜索。

| 内容方向 | 搜索词示例 | Hashtag示例 | 希望积累的内容 |
| --- | --- | --- | --- |
| AI视频基础 | AI generated video、AI short film、cinematic AI video | #aivideo、#aigenerated、#aifilm | 明确由AI表达的成片创意 |
| 微缩与场景创意 | miniature world AI、tiny world AI、miniature cooking AI | #miniatureworld、#aivideo | 微缩人物、商品与场景关系 |
| 拟人角色 | AI animal story、AI cat cooking、AI character animation | #aianimation、#aicharacter | 拟人角色、表情、动作和情节 |
| 商品表现 | AI product video、AI product commercial、AI product animation | #aicommercial、#productanimation | 商品演示、卖点视觉化和转场 |
| 视觉变化 | AI transformation、surreal AI video、AI visual storytelling | #aitransformation、#surrealart | 开头吸引力、形变和视觉反差 |
| 按目标品类扩展 | beauty product AI video、home gadget AI commercial等 | AI标签与具体品类标签组合 | 与客户当前商品相关的AI表达 |

不单独以“viral”“fyp”或泛带货标签作为主要搜索方向，以免偏离AI内容目标。关键词命中只说明可能相关，不能代替AI判断及素材审核。

**一次内容维护的操作顺序**

1. 先查看推荐流，记录当前方向及无关内容类型。
2. 推荐方向不足时，搜索目标词或hashtag，优先打开符合预期的成片内容。
3. 对有参考价值的视频查看完整表达，必要时查看作者近期公开作品，关注持续输出相关内容的账号。
4. 回到推荐流，继续浏览并观察推荐组成；正式日采仍以推荐流为来源。
5. 将值得采集的推荐视频记录为候选，保留源链接和“值得参考的点”；搜索结果和作者主页用于养号，不在本期单独扩展为另一套批量采集来源。

**对不同视频采取什么动作**

| 视频情况 | 观看与反馈建议 |
| --- | --- |
| 明确相关且有参考价值 | 观看完整视频，理解开头、演示与结尾；有学习需要才回看片段；确实认可时人工点赞或收藏 |
| 暂时无法判断 | 继续看到足以判断内容方向的位置，不因为有AI标签就直接认定相关 |
| 明确无关 | 确认无关后及时划走；反复出现同类无关内容时使用“不感兴趣”等现有反馈功能 |
| 同一创意大量重复 | 不反复观看或收藏每个版本，只记录最有参考价值的版本 |
| 教程、工具介绍但没有目标成片 | 可用于运营了解内容，原则上不占主精选池，避免推荐长期转为软件教程 |
| 高质量但作者粉丝超标 | 可作为养号方向参考，不进入本期小账号精选池 |

不设置每天必须点赞、评论或关注多少次的配额，也不安排批量评论、私信或循环播放。养号账号在TikTok的收藏用于运营发现；用户在本产品内的收藏独立维护。

**频率、白天与夜间**

建议每日维护，周复盘；不以每周集中操作一次替代日常检查。初期可安排北京时间09:30和20:30两个维护窗口，每次15–20分钟，主要为了便于交接并覆盖不同观察时段；夜间采集与人工维护分开。

没有依据将“晚上操作”设为推荐更精准的保证。需要比较时，可在连续两周内轮换早、晚的主要维护窗口，记录相同数量推荐样本的相关率和新增合格素材数，结果作为运营参考，不宣称严格的算法因果结论。

时间统一记录北京时间；涉及当地观察时段时，额外记录具体时区。美区不能按单一“当地晚上”处理，也不能用固定时差忽略夏令时。

**采集对账号推荐的影响**

采集涉及浏览推荐流，可能产生播放或跳过记录，不能默认对账号偏好没有影响。接入试采期间比较采集前后的推荐相关性；采集任务不执行统一点赞、关注或为完成采集而强制长时间播放。若相关性持续下降，应调整采集行为和维护安排后再提高采集量。

**地区扩充节奏——建议**

| 阶段 | 建议安排 | 扩展条件 |
| --- | --- | --- |
| 第1–2周 | 跑通美区主账号、采集、审核和产品分发 | 记录真实合格率、耗时及用户使用情况 |
| 第3–4周 | 稳定美区供给，完成同方向备用账号验证 | 连续两周有稳定发布，异常能够处理，审核产能可承接 |
| 第5–6周起 | 若有客户需求，试点一个东南亚国家；可优先评估马来西亚，再按需求决定是否改为其他国家 | 有当地语言审核人员、独立种子词和可用账号 |
| 下一轮稳定后 | 每2–4周评估增加一个国家；南美可先评估巴西葡语内容 | 上一市场已验证价值且没有挤占现有审核能力 |

以上为最早评估节奏，不按周数自动上线。每个新市场先完成小批内容验证，建立独立市场标签和供给统计；未经产品明确开放，不混入美区用户队列。不增加前台筛选栏来替代市场分发规则。

### 6.4 数据采集规则

**来源和每日数量**

采集对象为已启用运营账号在TikTok推荐流中遇到的公开视频，记录实际来源账号和采集时间。不能假设存在能够直接导出该账号推荐流的官方接口；研发需用真实账号验证可行的访问和采集方式，再确定实现方案。

每日300条指当日取得必要基础信息、通过初筛且与已有候选及素材记录去重后的新增候选。扫描过的视频、重复视频、获取失败和基础条件不合格的视频分别统计，不计入300条。

达到300条或到达06:00，结束新增采集，以先发生的条件为准。因供给不足或访问异常未达到目标时，记录实际数量和原因，不无限延长任务，不抓取无关视频补数。

**采集条件**

| 条件 | 规则 |
| --- | --- |
| 时长 | 必须在5–120秒内；无法获取时长的记录进入待补充，不进入有效候选计数 |
| 来源市场 | 首期为按美区目标维护的账号推荐流；这不等于其中每条视频都发布于美国 |
| 内容适配 | 语言、场景及题材适合目标用户；明显不匹配地区的内容过滤或进入人工复核。源视频国家有可靠信息才记录，无信息不伪填“美国” |
| 作者粉丝 | 能确认入选时小于10,000；缺失时补充后再决定，不用播放量反推粉丝数 |
| 发布时间 | 建议优先近30天发布；30天以前的内容不自动进入日采候选，可由运营说明参考价值后例外复核。原始日期必须保留 |
| 内容形式 | 公开短视频成片；不采集直播、图集冒充视频、明显无关教程或个人动态 |
| AI方向 | 优先有AI相关说明或视觉线索；无法确认时进入待审核，不把关键词当作最终证据 |
| 视频比例与清晰度 | 优先竖屏9:16；其他比例不拉伸、不截断关键信息。建议目标清晰度720p及以上，低清样本由运营判断能否看懂，不按单一分辨率替代内容判断 |
| 声音 | 有声音时需与画面匹配；本身为静音视觉创意的不因无语音而排除 |
| 热度 | 保存真实单视频播放和互动数据，作为精选参考；首期不设未经样本验证的统一播放量／点赞量门槛 |
| 去重 | 同一平台视频只保留一条；相同内容重复上传或轻微修改，由内容相似检查或人工复核处理 |

不能以“有商业标签”“播放量高”替代AI创意和小账号条件。近30天是视频原始发布时间的预选规则，近7天是本产品内容池的展示窗口，两者分开。

**采集字段**

| 字段组 | 必要内容 | 缺失处理 |
| --- | --- | --- |
| 素材身份 | 平台视频标识、源视频链接、作者标识、来源运营账号 | 无法确认同一素材或源地址则不入有效候选 |
| 内容信息 | 原始标题／文案、封面、视频时长、原始发布日期 | 标題为空保留事实，不虚构源文案；时长或日期缺失需补充 |
| 作者信息 | 名称、头像、粉丝数、粉丝数据获取时间 | 粉丝数缺失待补充；头像缺失可使用默认头像 |
| 互动信息 | 播放、点赞、评论、源收藏、分享等实际可取得指标及更新时间 | 单项缺失记为未知，不填0，不编造 |
| 来源与时间 | 来源账号、目标市场、采集时间、采集批次 | 用于追踪任务及区分采集日期与发布日期 |
| 内容判断 | AI判断及依据、参考价值、审核结果和原因 | 发布前补齐，不能用审核通过标记代替具体结论 |
| 文件与使用状态 | 转存状态、播放校验结果、下载及参考创作的可用状态 | 转存或播放不通过不得发布到正常视频流 |

首期互动指标采用最近一次成功获取的快照，保留获取时间，不承诺实时变化。再次采集到同一视频时可更新其数据，但不新建素材；用户刷新页面、打开收藏不会触发即时TikTok采集。历史收藏保留最近一次可用数据。

**夜间执行安排——建议**

| 北京时间 | 任务 | 结束要求 |
| --- | --- | --- |
| 00:00前 | 检查账号状态、来源范围、任务目标及历史去重记录 | 异常账号提前退出当夜任务并告知负责人 |
| 00:00–05:30 | 分批采集；基础检查通过后即可开始转存 | 避免把全部处理堆积到临近截止 |
| 05:30–06:00 | 补齐可恢复的采集失败项、收尾并汇总 | 06:00结束本轮新增采集，标记完成、部分完成或失败 |
| 06:00后 | 完成转存及二次审核，汇总已通过素材 | 未完成转存和审核的不发布 |
| 建议08:00 | 发布首批已通过素材，后续合格内容可分批补充 | 不要求08:00前强行审核完300条；不足时使用历史合格供给 |

06:00是采集截止，08:00是本方案建议的首批发布时间，两者不能混用。若业务要求06:00前连同审核和发布全部完成，应单独调整夜间审核排班及产能，不能只修改任务时间文字。

**失败与重试**

普通网络或单视频获取错误，建议最多自动重试2次，且不越过当轮截止时间；重复获取同一视频不会产生重复素材。登录验证、访问受限和账号异常不进入普通重试，暂停并通知运营处理。

某条失败不阻断其他正常素材处理；整批失败时共享池仍提供历史合格内容。失败记录包括时间、账号、环节及原因，不仅显示“失败”。

### 6.5 数据转存与文件校验

采集基础检查通过后，将需要上架的视频文件及封面转存到产品可稳定访问的存储位置，同时保留源链接、作者信息和原始发布日期。播放器、下载与创作参考使用同一条素材的正确文件，不能将临时网页链接当作永久素材文件。

转存后至少检查：

1. 文件可以打开并播放，时长符合要求，无明显截断、黑屏或损坏。
2. 文件、封面、标题和源链接对应同一条视频。
3. 横竖比例正常，有声音的素材音画匹配；不通过拉伸或裁切损坏参考内容。
4. 重复任务复用已有素材记录；不能因更换封面或跨日采集生成新视频身份。
5. 不去除作者标识或水印来伪装原创。素材可展示、可下载、可作为参考的使用范围需要分别确认并保存状态。

建议状态为“待转存、转存中、转存成功、转存失败”。转存失败允许重新处理；成功不等于审核通过，不能自动进入用户队列。

共享池7天展示期限不是文件删除期限。用户已收藏或已有项目引用的素材不得因退出7天窗口被自动删除；存储清理需先核实引用及使用状态。因投诉、内容风险或明确使用限制需要停用时，可以独立下架并保留用户收藏的必要说明。

### 6.6 二次审核与发布规则

**基础初筛和二次审核分别做什么**

基础初筛发生在采集阶段，主要排除明显不符合时长、来源、粉丝、形式及重复条件的内容。二次审核面向已经转存的实际视频，检查内容安全、AI相关性、学习价值和文件质量，不能只审核标题或封面。

首期建议由自动检查辅助、运营人员对拟发布视频逐条确认。已有内容审核服务是否可用，由研发核实；如暂不可用，采用人工审核并按产能发布，不能把“未调用审核”当作“审核通过”。

| 审核维度 | 必须检查的内容 | 处理方式 |
| --- | --- | --- |
| 内容安全 | 色情裸露、性暗示、涉及未成年人的不适宜内容、暴力血腥、仇恨歧视、危险行为、违法内容等 | 明确违规则不通过；不确定则待复核 |
| 政治及敏感议题 | 政治宣传、人物煽动、战争冲突等与AI创意参考无关的争议内容 | 首期不纳入精选，不仅依靠单个关键词判断 |
| AI相关性 | 成片是否符合本次AI内容方向，是否有足以支持判断的说明或证据 | 疑似但不能确认则待补充，避免把真实拍摄误标为AI |
| 学习价值 | 至少有一个可描述的题材、开头、演示形式、视觉表达或节奏亮点 | 运营记录一句推荐理由；仅“热门”不能作为理由 |
| 无关内容 | 日常动态、自拍聊天、普通真人短剧、纯教程、无关娱乐搬运等 | 与目标无关则不通过；有价值的非带货AI创意不因缺商品而排除 |
| 重复与搬运 | 同一视频、重复内容、仅变更字幕或封面的版本 | 原则上保留最有参考价值的版本；无法确定时人工判断 |
| 可用质量 | 完整播放、内容一致、画面可理解、音画正常、源信息正确 | 不符合则退回处理或不通过 |
| 夸大与误导 | 明显虚假的商品功效、危险示范、需要依赖错误信息才能成立的内容 | 不通过或进一步复核，不鼓励用户模仿错误表达 |

自动审核返回不确定、超时或失败时，素材进入待复核，不默认放行。安全审核通过也不能替代AI属性和参考价值审核。

**状态与操作**

| 状态 | 用户能否看到 | 运营后续操作 |
| --- | --- | --- |
| 待审核 | 否 | 查看完整视频、基础信息和检查结果，填写结论 |
| 待补充／待复核 | 否 | 补齐信息或人工复核后返回审核；保留原因 |
| 不通过 | 否 | 记录原因；纠正信息后可重新提交，不直接发布 |
| 已通过、待发布 | 否 | 确认文件和页面信息可用后发布 |
| 已发布 | 是 | 进入共享池；允许更新数据，不重置首次发布日期 |
| 已下线 | 不再进入新队列 | 记录原因；已有收藏保留对应状态和必要说明 |

审核人与发布操作者、时间和结果需要留痕，可以由同一人员完成，不强制增加多级审批。发布前再次确认文件可用、状态通过、数据对应同一视频，防止审核完成后文件失效。

**审核产能与300条的关系**

300条是每日候选目标。以平均每条完整审核90秒举例，300条需要约7.5人时，尚未包含异常处理。该数字仅为排班计算示例，实际上线前应按真实视频长度和审核耗时测算。

首期逐条审核，不要求每日300条全部上线。可先发布已完成审核的部分，剩余继续处理；如果日均新增持续超过处理能力，需要降低新增候选目标或增加审核投入，经产品确认后执行，不能让待审队列长期累积。

### 6.7 共享池、分发与消费规则

**入池与时间口径**

采集池仅供内部处理，共享池只包含已发布素材。正式入池日期是素材首次发布到共享池的北京时间日期；原始发布时间、采集时间、审核时间分别保留。

今日入池不表示视频今天才发布到TikTok。相同视频跨日重采或只更新互动数据，不重新算作今日内容，也不重置用户观看记录。

**分发顺序**

1. 先展示今日共享池中该用户未看内容。
2. 今日看完后，展示昨日共享池中未看内容。
3. 再展示近7天剩余日期中的未看内容。近7天包含今天和前6个自然日，不重复前两层。
4. 各层内按用户独立随机顺序展示，不因刷新重新洗牌。

每个用户拥有独立观看队列及历史记录，用户之间允许看到同一视频。一个用户看过，不从公共共享池删除，也不影响其他用户。

**观看记录与队列稳定性**

- 当前视频成功展示并开始播放后，记为“已展示”，用于自动下发去重；预加载、仅进入加载态或加载失败不计入。
- “已展示”不等于看完；如需分析观看完成，另行记录实际播放行为，不混用指标。
- 用户主动上翻、从我的收藏打开、主动重看允许重复，不被已展示去重阻止。
- 页面刷新不触发额外TikTok采集、不清空观看记录，也不重排已有剩余队列。
- 新素材发布后，在下一次获取待播内容时进入对应日期层；当前视频和已加载的前后顺序不被强制打断。
- 跨日时按新的北京时间日期重新归属待分发内容。正在播放的视频保留到切换；退出窗口或已下线内容不继续进入新的待播队列。

上述保留当前播放仅适用于正常跨日或退出时间窗口。因内容风险、投诉或明确使用限制下线时，应同步使已加载队列中的对应条目不可用，并停止相关操作；用户看到说明后可以切换下一条。

**终点与异常**

当近7天符合条件的内容全部看完，提示“近7天精选已看完，稍后再来看看”，可进入我的收藏。不只提示“今日暂无更多”而掩盖还有历史内容可看。

没有任何可展示内容时显示“精选内容准备中，请稍后再来”；采集或审核未完成时不展示未经审核的视频。单条视频加载失败提供重试及下一条，不将失败计为成功观看，也不因一次失败将素材永久下线。

**收藏保留**

7天仅限制默认浏览供给。已收藏内容不因超过7天从“我的收藏”删除；取消收藏只删除个人关系。公共素材和已创建项目均保留原有状态。

### 6.8 运行监控与日常复盘

每日需要看到以下结果，优先复用现有任务管理能力，不强制新增复杂看板：

| 环节 | 需要看到的结果 | 异常处理 |
| --- | --- | --- |
| 账号 | 可用账号、推荐相关率、异常及负责人 | 暂停异常账号，确认备用账号是否可接管 |
| 采集 | 计划量、扫描量、有效候选量、重复量、失败量、完成时间 | 06:00未达目标标为部分完成并说明原因 |
| 转存 | 成功、待处理、失败数及原因 | 可恢复项重试，不影响其他合格素材 |
| 审核 | 待审、通过、不通过、待复核、审核耗时 | 待审积压时调整产能，不绕过审核 |
| 发布 | 当日新发布数、当前近7天可用量 | 新内容不足时使用合格历史供给 |
| 用户使用 | 有效播放、收藏、收藏回访、复刻提交及生成结果 | 用于调整选题和供给方向，不替代内容审核 |

每天检查异常和待处理项，每周复盘一次内容方向。原始观看量、用户收藏和创作行为作为产品指标单独记录，不写回为TikTok互动数据。

**导航与展示**

- 位于“发现”下，二级菜单顺序为“灵感发现 → UGC爆款 → 品牌追踪”。
- 视频居中大幅展示，保持原比例，标题位于视频底部，播放控件可用。
- 右侧上方展示作者头像、名称和粉丝数；横线分隔下方发布日期、播放量。四个操作按钮放下方。
- 点赞、评论、源收藏、分享分别展示对应数值；播放量保留在右侧信息区域。缺失指标显示“—”或隐藏，不补0。
- 产品收藏使用与我的收藏一致的书签图标；源视频收藏量使用五角星，二者语义独立。
- 不恢复今日精选角标、视频左下角作者信息、数据更新时间脚注、“TikTok源视频数据”标题或独立“查看作者”按钮。

**标题文案**

默认显示1–2行。只有超出时才显示“更多”；点击后展开完整文案，显示“更少”。展开内容过长时限制在视频内部可用区域并允许滚动，不覆盖播放操作；切换视频后恢复收起。

**播放与切换**

用户可播放／暂停、拖动进度、静音及上下切换。上翻最多回到本次浏览历史中的第一条；到顶后不再继续。切换时暂停上一条，避免多个声音同时播放。

加载失败显示错误、重试及下一条入口。首次自动播放如被浏览器阻止，提供明确播放入口，用户主动播放成功后再记录已展示。

**收藏**

点击收藏后变为“已收藏”，提示“已收藏到我的收藏”，可点击“查看”进入“资产 → 我的收藏”。同一用户、同一视频只保留一条收藏，重复点击及跨日重复采集不新增。

再次点击取消，提示“已取消收藏”。UGC和我的收藏同步状态，仅删除个人关系，不删除共享素材、他人收藏或已创建项目。

**下载**

下载当前素材对应的视频文件，显示处理中、成功或失败反馈。失败说明原因并允许重试；不可用或不允许提供下载时禁用并给出原因，不下载错误文件或源网页。

**一键复刻**

将当前视频作为参考自动带入现有高保真复刻流程。用户补充商品及必要输入后，可以提交生成并查看新项目与结果。不能只跳转空白创作页却标为已带入素材。

入口使用前检查参考文件是否仍可用，异常时提示原因并保留当前浏览位置。该流程的输入限制按现有创作能力校验；不承诺采集到的所有视频格式都无需处理就能提交。

**查看源视频与作者**

“查看源视频”在新标签页打开当前视频的官方源链接，保留站内位置。点击作者区域可进入有效的作者源主页。文案统一使用“源视频”。

### 7.2 我的收藏

【图片占位：资产—我的收藏列表】

【图片占位：我的收藏—素材详情弹窗】

**入口与列表**

位于“资产 → 我的收藏”。默认按最近收藏倒序，支持搜索标题或作者，分页展示。界面不展示顶部“UGC爆款”标签、条数、最近收藏切换控件、收藏时间或视频列表顶部空白横栏。

每张卡片展示封面、标题、时长及可用数据。作者头像、名称与粉丝数放一行，播放量与原始发布日期放一行。操作文案为“查看、下载、一键复刻”，收藏图标与UGC产品收藏一致。

**详情弹窗**

点击封面或“查看”，在当前页面打开详情弹窗。支持播放／暂停、拖动、静音，展示与UGC一致的标题、作者和视频数据；长文案采用同样的“更多／更少”逻辑。关闭弹窗停止播放，回到原卡片位置，保留搜索词和页码。

弹窗中的收藏、下载、复刻、源视频和作者入口与UGC一致。若保留上下切换按钮，只切换当前收藏结果中的素材，不跳入UGC推荐队列；达到边界时禁用相应按钮。

**取消收藏与空态**

取消后卡片移出列表并提示“已取消收藏”，UGC同步为未收藏。若正在详情中取消，关闭该条详情并返回更新后的列表；当前页为空时回到最近的有效页。

无任何收藏时展示“还没有收藏，去UGC爆款发现灵感”，主按钮为“去UGC爆款”。搜索无结果展示“没有找到相关收藏”，提供“清空搜索”，不误判为从未收藏。

**失效素材**

超过7天继续保留。站内文件确认不可用时保留卡片、标题及来源，标记“视频暂不可用”，停用播放、下载和复刻，仍可取消收藏及访问有效源链接。

源视频链接失效与站内文件不可用分别记录：仅源链接不可访问，不自动断言站内文件也失效；若因内容审核、投诉或使用限制下线，则按下线原因停用相应能力。不能因为一次网络失败永久删除收藏。

### 7.3 运营支撑能力

本期需要一个可用的内部管理入口，也可以复用现有工具，至少满足以下操作：

| 操作 | 所需信息与行为 |
| --- | --- |
| 账号维护 | 查看市场、负责人和状态；启用／暂停采集；记录异常与恢复情况 |
| 采集任务 | 查看当夜任务目标、实际结果、失败项；按规则重试，不因重试重复建素材 |
| 审核列表 | 按待审核、待补充、通过、不通过筛选；播放实际文件、查看源内容及基础数据 |
| 审核操作 | 填写AI判断、推荐理由、结论与原因；通过／不通过／退回补充 |
| 发布管理 | 只允许发布转存及审核通过的素材；下线需填写原因；保留操作记录 |
| 数据纠错 | 修正标题、作者或指标错误时同步前台；不修改视频身份或重置首次发布日期 |

普通产品用户只能浏览和管理自己的收藏，不能查看运营账号信息、未审核素材或执行发布操作。

## 9. 物料准备

### 9.1 上线所需物料

| 物料 | 数量或要求 | 负责人 |
| --- | --- | --- |
| 主来源账号 | 已有1个TikTok账号，核实当前推荐相关性、可访问性和恢复方式 | 运营 |
| 备用账号 | 建议1个同市场、同内容方向账号，达到备用标准后启用 | 运营 |
| 种子词与内容样例 | 覆盖AI成片、微缩、拟人、商品演示等方向；含应排除样例 | 产品、运营 |
| 冷启动内容 | 300条已审核、可播放素材，记录真实原始日期；批量首次发布时进入当日共享池 | 运营、采集与研发 |
| 采集及转存样本 | 含正常、重复、失败、字段缺失、格式异常等状态，用于验证真实链路 | 采集与研发 |
| 审核能力 | 可用的自动审核服务或明确的人工处理方式；有复核负责人 | 研发、运营 |
| 审核排班 | 根据实测每条审核耗时安排，明确早间首批和后续发布责任人 | 运营 |
| 产品原型 | UGC收起／展开、我的收藏、详情弹窗及必要异常状态 | 产品、设计 |
| 创作验证素材 | 能覆盖参考输入、提交生成和结果查看的真实样本 | 产品、研发 |

冷启动内容积累后，发布前需重新确认源信息、文件及审核结果仍有效；不能因积累时间较长直接免检。若尚未凑齐300条，评审时明确缺口和上线调整，不把300条候选表述为300条合格素材。

### 9.2 技术评审需要明确的事项

以下事项不阻止需求范围确定，但需要在排期前用真实账号和素材确认：

| 事项 | 需要形成的结论 |
| --- | --- |
| 推荐流采集方式 | 当前账号推荐内容如何取得、哪些字段可取、任务能否在窗口内完成；不假设未验证的接口存在 |
| 媒体转存及使用 | 视频和封面能否稳定获取，展示、下载与参考使用范围如何确认，失败如何处理 |
| 推荐偏好影响 | 采集过程产生哪些浏览行为，是否使账号方向明显变化，如何监控和调整 |
| 审核能力与产能 | 自动服务覆盖哪些风险、失败如何转人工；谁确认AI与学习价值，预计每日能审多少 |
| 一键复刻适配 | 5–120秒内不同素材如何符合现有参考输入要求，无法适配时怎样提示和处理 |
| 时间与人员 | 06:00采集截止不变；建议08:00首批发布是否有人力承接，以及后续批次安排 |
| 文件保留 | 退出7天窗口但已收藏或被项目引用的文件如何保留，失效与下线如何同步 |

### 9.3 底部落地安排

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |
| 第一步：真实链路验证 | 用已有主账号取得一小批推荐视频，验证字段、转存、审核、站内播放和参考创作 | 拿到端到端可用样本，并明确失败状态，不能仅证明能获得视频链接 |
| 第二步：补齐运营供给 | 建立种子词、日常维护、账号备用、夜间任务及审核排班，准备冷启动内容 | 来源和负责人明确，采集及审核产能经过实际测量 |
| 第三步：产品联调上线 | 对接共享池、独立队列、我的收藏、下载和复刻，完成A01—A20 | 用户可完整体验“观看参考 → 收藏 → 进入创作”，异常不突破审核边界 |
| 第四步：运行复盘 | 连续观察两周的供给稳定性、相关率、收藏回访和创作提交 | 按实际问题调整养号、选题和审核，不以单纯提高采集量替代质量 |
| 后续：地区扩充 | 按第6.3节逐个市场验证 | 原市场稳定、新市场有人审核、有用户需求，再开放对应供给 |

研发排期以第一步的真实链路验证为依据。运营养号、备用账号准备和样例整理可以同步推进，无需等待所有前台功能完成。
