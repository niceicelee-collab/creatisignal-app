# 素材分析与高保真复刻字段优化方案

版本 V1.0　日期 2026年9月11日　用途 产品与设计评审

## 1 优化结论与范围

建议将三个结果页分别收敛为：**素材分析看借鉴点，复刻拆解看沿用结构，新脚本看成片内容。** 主页面优先展示用户做判断所需的信息，重复解释合并，生成所需的详细描述保留在生成流程中，不要求用户逐项阅读。

本期优先完成字段与阅读结构优化，按当前以只读为主的使用方式设计。后续在同一组内容上开放口播与关键画面描述编辑，避免再次更换用户熟悉的页面结构。

| 页面 | 用户需要完成的判断 | 本次处理范围 |
| --- | --- | --- |
| 图1 素材分析结果 | 视频讲了什么，有哪些值得借鉴的表达 | 优化字段与拆解呈现，保留独立分析价值 |
| 图2–3 复刻第一步 | 原视频的表达结构是什么，准备沿用什么 | 重点精简策略与逐段信息，移走重复的对象说明 |
| 图4–5 复刻第三步 | 新商品将怎样出现，成片会说什么和展示什么 | 重点重组为可通读的脚本，为少量编辑预留位置 |
| 图6 商品确认 | 换成哪个商品和人物，资料是否准确 | 仅调整与前后步骤重复或冲突的信息 |
| 图7 视频结果 | 成片是否符合脚本，如何下载或再调整 | 仅调整返回入口与版本信息的衔接 |

### 当前页面的主要问题

- **语义重复。** 整体策略、阶段策略、创意描述、关键信息、画面内容，多次描述同一件事；用户需要自己判断哪些是新增信息。
- **阅读层级过深。** 阶段中再折叠分镜，一张卡片承载大量文本；第三步很难连续读完整条脚本。
- **展示粒度混杂。** “叙事阶段”“分镜”和逐秒镜头描述并存。截图中的一个“分镜”实际包含多次镜头切换，不适合继续作为唯一的阅读单位。
- **只读内容像表单。** 大量边框容器以及空白口播框容易暗示可编辑或尚未填写；还会放大无口播视频的空白占比。
- **步骤职责重复。** 第一步详列商品、人物、环境，第三步再次展开完整策略，都挤占了当前任务真正需要的信息。

### 方案选择

| 方向 | 收益与代价 | 建议 |
| --- | --- | --- |
| 按任务合并字段，核心内容直接可读 | 同时减少信息量和理解成本，需要整理摘要规则 | 采用 |
| 保留所有字段，只做默认折叠 | 改动较小，但冗余和深层查找仍然存在 | 仅用于少量补充细节 |
| 大幅删除，只展示视频与一句结论 | 页面很轻，但难以确认口播和商品表达 | 不作为主方案 |

## 2 统一信息规则与页面分工

### 字段按用途处理

| 处理方式 | 适用内容 | 呈现规则 |
| --- | --- | --- |
| 保留 | 原视频、时间范围、画面要点、实际口播和字幕 | 放在主阅读区，重要内容可直接读到 |
| 合并 | 策略、创意描述、关键信息中的重复意思 | 输出一个面向用户的短描述，不拼接原文 |
| 按需查看 | 详细拍法、识别对象补充信息、可复制提示词 | 只保留有明确用途的入口，最多进入一层详情 |
| 移到所属步骤 | 完整商品、人物资料及替换配置 | 统一放在商品确认页，不在第一步重复铺开 |
| 从用户页面移除 | 情绪曲线、重复策略解释、内部讲述者标记等 | 不转移到“全部详情”中继续堆放 |

这里的“移除”指用户展示层。画面约束、时间信息、商品特征和人物一致性等生成所需信息仍须保留；展示精简不应降低生成输入的完整性。

### 三个页面保留各自的重点

| 信息 | 素材分析结果 | 复刻第一步 | 新脚本确认 |
| --- | --- | --- | --- |
| 视频与定位 | 原视频，可定位片段 | 原视频，可定位片段 | 按需打开原视频作为参考 |
| 全局摘要 | 一句话创意与主要借鉴点 | 一句话沿用思路 | 商品与内容形式等简短概览 |
| 逐段画面 | 原片画面要点 | 原片画面要点与沿用重点 | 新商品最终画面要点 |
| 原片为什么这样表达 | 保留简短解释 | 仅保留影响复刻的部分 | 主视图不再解释 |
| 口播与字幕 | 展示实际内容 | 展示实际内容 | 展示本次生成将使用的内容 |
| 商品和人物完整资料 | 按需识别详情 | 移至第二步 | 仅显示当前选定对象摘要 |

### 内容压缩规则

- 全局摘要建议为一句话，中文约40–60字；全局借鉴点最多3条，每条表达一个具体做法。
- 段落标题建议8–16字，例如“产品细节开场”“公园骑行展示”，优先描述用户看得到的内容。
- 每段画面要点优先1–2句，必要时列2–3个动作。压缩时保留主体、动作、关键商品特征和不可遗漏的品牌或文字信息。
- 短文案只是展示建议，不能成为截掉价格、规格、适用条件或口播内容的硬限制。长口播仍须完整可读。
- 主视图只区分“概览”和“段落内容”。段落详情按需打开，不再嵌套“阶段 → 分镜 → 内容”的多层折叠。
- 统一使用“开场吸引”“场景展示”“使用演示”“品牌收尾”“引导行动”等中文名称，内部的 Hook、transition 等不直接外露。

**分析判断和视频事实要分清。** 画面和原文属于观察结果；受众、吸引力、说服逻辑属于分析推断。“为什么有效”建议改为“可借鉴点”，避免把内容解读呈现为已验证的效果结论。

## 3 素材分析结果页字段优化

图1承担独立分析任务，用户可能只想理解素材，并不立即复刻。因此保留借鉴价值解释，但减少术语和重复说明。

| 当前字段或模块 | 处理 | 优化后的字段与位置 |
| --- | --- | --- |
| 名称、状态、时长、生成时间、镜头与元素数量 | 精简 | 标题区保留名称、状态、时长；其他进入任务信息，内部元素数量不展示 |
| 叙事策略全景与整体策略 | 合并改名 | “创意概览”，一句话说明核心表达 |
| 目标受众 | 降级 | 有助于判断时显示一条“适合人群”；推断使用“可能面向” |
| HOOK机制 | 合并 | 进入“可借鉴点”的开场项，不重复粘贴口播 |
| 说服路径 | 合并 | 以段落顺序展示，必要的解释进入借鉴点 |
| 情绪曲线 | 移除 | 不保留独立字段，也不换成另一组抽象标签 |
| 场景拆解与场景数 | 改名 | “视频段落”；按表达目的组织，数量放在标题旁 |
| 阶段标签、长标题、时间范围 | 精简 | 短标题＋时间范围；阶段类型作为次要标签 |
| 为什么有效 | 改名精简 | “可借鉴点”，每段最多一句具体解释 |
| 旁白 | 保留改名 | “口播”；有人物说话或画外音时展示实际文案 |
| 镜头字段如“主持人 在场” | 合并 | 必要的出镜信息融入画面要点，不单列存在状态 |
| 视频描述 | 拆分 | 主视图显示“画面要点”；逐秒拍法放入“查看拍法” |
| 提示词反推与语言复制操作 | 降级 | 放入“复制创作提示词”入口，打开后再选择语言并复制 |
| 原视频、时间轴、去复刻、分享 | 保留 | 视频与段落定位联动；“去复刻”为主操作，分享为次要操作 |

### 默认页面如何呈现

左侧固定原视频和段落导航；右侧上方展示一条创意概览与最多3条借鉴点，下方展示完整段落列表。每段默认显示标题、时间、画面要点和实际口播；有独立画面文字时追加字幕内容。少量补充拍法通过行内入口查看。

不再默认打开一张特别高的卡片、让其他段落只剩标题。段落过多时提供简短导航，阅读区仍按时间顺序排列，用户可以连续阅读。

### 图1内容的压缩示例

**创意概览：** 以错过利润的提醒开场，再展示库存与款式，最后引导到店。

**开场吸引　0.0–4.2秒**

画面要点：男子在服装货架前面对镜头讲话，穿插黑底大字，突出“正在错过赚钱机会”。

口播：“Vocês estão perdendo de ganhar dinheiro.” 中文释义按需查看。

可借鉴点：开场直接点出目标客户关心的利润机会，并用大字强化信息。

口播原文与翻译分开；画面字幕若只是逐字重复口播，可标注“字幕同口播”，不复制两遍。若有增删，仍须分别展示。

## 4 复刻第一步字段优化

图2–3的目标是让用户快速理解参考视频，并进入新商品确认。建议页面名称调整为“查看参考视频拆解”，说明文案为“了解视频结构，确认本次沿用的表达方式”。原有四步流程无需增加步骤。

| 当前字段或模块 | 处理 | 优化后的字段与位置 |
| --- | --- | --- |
| 策略摘要与整体策略 | 合并 | “复刻思路”，一句话概括沿用的表达方式 |
| 目标受众 | 降级 | 仅在影响理解时，作为摘要中的补充说明 |
| HOOK机制 | 合并 | 进入开场段的“沿用重点” |
| 说服路径 | 合并 | 用段落列表表达顺序，取消重复长段文字 |
| 情绪曲线 | 移除 | 不参与当前步骤的确认 |
| 叙事结构、阶段类型、阶段标题、时间 | 合并 | “视频段落”，每行短标题＋时间范围 |
| 阶段创意策略 | 合并 | “沿用重点”，每段一句，仅保留可迁移的做法 |
| 创意描述 | 合并 | 与画面内容共同压缩为“画面要点” |
| 关键信息标签 | 合并 | 将必要事实写入画面要点，取消单独标签区 |
| 分镜编号、时长、嵌套折叠 | 精简 | 统一按段落阅读；只有查看详细拍法时呈现内部镜头信息 |
| 画面内容中的逐秒运镜描述 | 降级 | 主视图只留画面要点，详细拍法按需打开 |
| 实际口播与画面字幕 | 保留 | 按内容存在情况展示；不显示空输入框 |
| 商品信息、人物信息 | 移位 | 完整资料放第二步，第一步只需“下一步替换商品与人物”的短提示 |
| 环境信息 | 合并 | “公园”“林荫步道”等必要场景进入对应段落，删除完整环境卡片 |
| 提示词反推 | 移出主流程 | 本页不展示长提示词；如需保留复制用途，放次要菜单入口 |
| 底部复刻边界说明 | 精简 | 靠近主按钮，以一行说明沿用与替换范围 |
| 重新拆解、立即复刻 | 调整文案 | “重新分析”为次要操作；主按钮改为“下一步 确认新商品” |

### 主页面保留三块内容

**参考视频。** 播放器与段落时间联动，暂停时优先显示能辨认商品的帧；未取得封面时提供视频名称与播放操作，避免用空黑块承担全部识别作用。

**复刻思路。** 一句话加一条范围说明。例如：“沿用产品细节开场、多场景骑行展示和品牌收尾；商品、人物与具体卖点在下一步确认。”不能将“高保真”解释为对原人物、商标或每个镜头的逐帧保证。

**视频段落。** 按顺序展示短标题、时间、画面要点、沿用重点，以及实际口播和独立字幕。无口播视频在概览中标一次，无须每段重复“无口播”。

默认不再铺开完整商品、人物、环境卡片。若同一个任务已经有可用的素材分析结果，页面应直接承接已有结果；是否重新分析由用户明确触发，不因切换页面重复增加等待。

## 5 新脚本确认页字段优化

图4–5应当帮助用户检查即将生成的视频内容。建议页面名称为“确认新视频脚本”，以完整、可通读的段落脚本为主体。原片分析、改写原因、生成拍法不与成片内容并列展示。

| 当前字段或模块 | 处理 | 优化后的字段与位置 |
| --- | --- | --- |
| 新创意策略摘要大卡片 | 替换 | 紧凑“视频概览”：新商品、预计时长、内容形式；语言等按需显示 |
| 创意策略 | 移出主视图 | 已在第一步解释，不再次要求用户阅读 |
| 目标受众、用户痛点、核心承诺 | 合并 | 有用部分写入实际画面或口播；不作为三项独立确认字段 |
| 使用场景 | 合并 | 放进对应段落画面要点，取消全局重复列表 |
| 情绪曲线 | 移除 | 不作为脚本阅读或编辑入口 |
| 叙事阶段数与分镜数 | 精简 | 标题旁显示“共4段”等用户阅读数量，技术分镜数按需查看 |
| 阶段类型、阶段标题、时间范围 | 合并 | 以短标题＋时间范围构成段落行头 |
| 每阶段创意策略 | 移出主视图 | 改写原因如有需要，通过“查看参考片段”理解 |
| 创意描述、关键信息 | 合并 | 进入“画面要点”，保留会影响生成结果的具体内容 |
| 分镜编号、重复时长、讲述者标记 | 精简 | 不重复显示；确有多人对话时以角色名区分文案 |
| 口播内容大输入框 | 按状态替换 | 当前显示只读正文；后续从“编辑口播”进入编辑态 |
| 画面内容长段落 | 重组 | 直接展示主体、动作与关键商品特征，详细拍法按需打开 |
| 画面字幕 | 单独保留 | 有独立字幕时展示；与口播一致时注明“字幕同口播” |
| 原片与新片差异 | 按需呈现 | 用“查看参考片段”做局部对照，不默认增加全页双栏对比 |
| 重新生成脚本 | 保留次要操作 | 与主按钮分开，避免误认为生成视频的必经步骤 |
| 模型、字幕方式、规格、积分、生成视频 | 分层 | 底部保留生成参数摘要、预计消耗与主按钮；通过“生成设置”调整细项 |

### 每段默认读什么

**行头：** 段落顺序、短标题、时间范围。**正文：** 画面要点；有口播时显示完整口播；有独立画面文字时显示字幕。每段只保留这些会进入成片、需要用户检查的内容。

前3–4段可以连续展开阅读，更长脚本通过滚动和段落导航访问。不得为压缩页面而默认截断全部口播；不要求用户逐一展开两层卡片才能读完内容。

本页尚未生成视频，不展示看似成片的播放器或伪预览。若使用原视频帧辅助理解，明确标注“参考原片”，不把原商品画面当作新商品效果。

口播、字幕、商品名称、关键规格、使用动作等会改变成片含义的信息不得只藏在拍法详情中。概览无需展示宽泛的“核心承诺”，但脚本中出现的承诺和条件必须完整可读。

## 6 同一条电动车素材的呈现示例

以下为页面内容写法示例。新商品的外观、部件与场景表达，以第二步确认的资料为准；示例不增加截图之外的性能承诺。时间范围采用截图中的展示值，最终页面需统一精度。

### 复刻第一步

**复刻思路：** 用产品细节吸引注意，再展示两类骑行场景，最后以品牌收尾。

**形式：** 无口播；音乐状态以音轨识别结果为准。无口播不等于无声。

| 段落 | 画面要点 | 沿用重点 |
| --- | --- | --- |
| 产品细节开场 0–5秒 | 展示薄荷绿色车身、轮毂和后轮结构，快速切换细节画面 | 用有辨识度的细节建立第一印象 |
| 公园骑行展示 5–12秒 | 展示人物在公园或林荫步道骑行 | 通过真实使用场景展示商品 |
| 街道骑行展示 12–17秒 | 展示另一人物在街道骑行 | 延续同一商品的场景变化 |
| 品牌收尾 17–18秒 | 品牌标识集中出现 | 保留短促清楚的收尾方式 |

**底部说明：** 沿用段落顺序与展示方式，下一步确认替换商品和人物。

**主按钮：** 下一步 确认新商品。

这里的品牌收尾没有购买号召，不应为了套用固定模板而改写成“引导下单”。

### 新脚本确认

**视频概览：** N6 Electric Trike · 预计18秒 · 4段 · 无口播。

| 段落 | 默认展示的画面要点 |
| --- | --- |
| 产品细节开场 0–5.3秒 | 在湖畔展示蓝黑车身，依次呈现轮胎、前悬挂和彩色显示屏，最后切到骑行画面。 |
| 公园骑行展示 5.3–11.6秒 | 人物在公园或林荫步道骑行，画面能看清骑行姿态与车身。 |
| 街道骑行展示 11.6–16.5秒 | 人物在街道骑行，展示车辆行进与使用场景。 |
| 品牌收尾 16.5–18秒 | 展示第二步已确认的品牌名称或标识；未确认时提示补充或去掉品牌画面。 |

该示例沿用截图中无口播的内容形式，不展示四个空白口播输入框。具体字幕或其他画面文字如存在，仍在所属段落展示。

### 有口播时的段落写法

**段落2 日常使用展示　画面要点：** 人物展示商品的实际使用动作。

**口播：** 完整展示目标语言文案；中文释义通过“查看翻译”打开。

**画面字幕：** 与口播一致时标注“字幕同口播”；优惠、价格、CTA等独立文字单独列出。

用户在主视图即可检查文案和画面是否匹配；景别、机位、运镜等补充拍法通过“查看拍法”进入一层详情。

## 7 当前只读与后续编辑边界

### 本期只读呈现

使用正文和清晰的字段标签，不使用可输入的表单外观。页面统一说明“确认内容后生成视频”；“可修改口播”等提示只有在实际能力已可用时才出现。

用户发现内容不合适时，沿用“返回修改商品信息”或“重新生成脚本”的现有路径。不要新增没有对应处理能力的“纠错”“局部重写”按钮。重新生成前保留当前可用脚本，失败后仍可查看。

### 后续优先开放的编辑内容

| 可编辑内容 | 编辑方式 | 边界与联动 |
| --- | --- | --- |
| 口播 | 每段一个“编辑口播”入口，进入后显示文案输入区 | 使用最终生成语言；保存后替换该段口播，不让用户修改分析策略 |
| 画面要点 | 每段一个“编辑画面”入口，修改主体动作和重点描述 | 商品、人物选择仍由第二步管理；不要求填写景别和运镜字段 |
| 独立画面字幕 | 后续开放单独文字编辑；可先于复杂画面编辑提供 | 与口播不同的价格、优惠、CTA等有明确归属，不与口播混成一项 |

阶段顺序、技术镜头拆分、逐秒时长、情绪曲线、策略推理与完整提示词，不作为首批编辑字段。增加口播、切换人物或改变故事结构，会改变多个段落，不应混入一次普通文案修改中。

### 编辑必须具备的行为

1. **保存与取消清楚。** 进入编辑态后展示“保存”“取消”；只读态保持紧凑正文，修改完成后可恢复该字段生成时的内容。
2. **明确正在编辑的语言。** 目标语言是成片使用的口播；中文释义用于辅助理解。修改译文不能静默替代目标语言文案。
3. **口播与字幕联动明确。** “字幕同口播”时修改口播同步更新字幕；独立字幕保持独立，提示用户检查内容是否一致。
4. **时长冲突就地提示。** 口播明显变长时，提示缩短文案或调整时长；提供估算须经过实际能力验证，不以固定字数承诺一定读完。
5. **关键商品变更回到确认步骤。** 修改商品规格、品牌或人物对象，应回第二步确认，并提示已有脚本需要更新，避免前后资料不一致。
6. **整稿重写不覆盖人工修改。** 已有编辑时，整稿重写前说明影响并让用户选择保留当前版本或继续；失败保留原稿，不反复要求确认普通保存。
7. **脚本与成片版本对应。** 修改脚本后提示“尚未生成新视频”；已有成片保持原版本，不把新文案显示成旧视频的生成依据。

用户可修改的是成片表达。生成所需的更详细描述应随关键内容保持一致，用户不需要再手动维护一份复杂描述来让修改生效。

## 8 页面呈现与特殊状态

### 布局建议

| 项目 | 建议呈现 |
| --- | --- |
| 素材分析与复刻第一步 | 左侧参考视频，右侧概览与段落列表；视频随阅读保持可访问 |
| 新脚本确认 | 中间以脚本为主；原片通过次要入口打开，避免两份长脚本默认并排 |
| 页面宽度 | 桌面内容区建议控制在1200–1440像素，居中；脚本文字行宽约760–900像素 |
| 视频占比 | 桌面左列约280–360像素；高度服从可用视口，不让播放器挤掉导航与底部操作 |
| 间距与字体 | 正文建议14–16像素、行高1.5–1.7；字段间距8–12像素，段落卡片间距12–16像素 |
| 颜色与层级 | 保留品牌绿，用于主操作和当前定位；次要信息使用中性色，避免多层整块绿色边框 |
| 卡片组织 | 以留白、分隔线和清楚标题组织；只读正文不套输入框；仅必要状态使用强调色 |
| 底部操作 | 固定操作区预留内容空间；显示预计消耗及关键规格，主按钮始终可见且不遮挡末段 |
| 较窄窗口 | 改为单列，视频在前、段落在后；不通过整体缩小字体容纳桌面双栏 |

以上尺寸用于下一步原型起点，最终需在1366×768和1920×1080等实际视口中检查；不能用缩小整页的方式证明布局可用。

### 内容状态规则

| 状态 | 用户应看到什么 |
| --- | --- |
| 确认无口播 | 概览标注“无口播”；各段不显示空口播框，不影响音乐或字幕显示 |
| 口播暂未识别或识别失败 | 明确显示“口播待识别”或“口播识别失败”，不能当作无口播 |
| 无独立字幕 | 不显示空字幕区域；如与口播一致，使用“字幕同口播” |
| 口播很长或存在多角色 | 完整换行展示；多角色使用角色名，取消内部讲述者标记 |
| 摘要缺失但段落可用 | 优先展示现有段落，省略空摘要；不编造策略，也不阻止阅读 |
| 原视频加载失败 | 提供重试入口，已取得的分析和脚本仍可读 |
| 脚本生成中或失败 | 明确当前状态；有旧稿时保留旧稿，失败提供重试 |
| 商品关键信息矛盾或遗漏 | 在受影响段落直接提示，并提供返回商品确认的入口，不藏入详情 |

### 基础可用性

段落定位、详情与生成操作支持键盘访问；焦点位置清楚可见，折叠状态有文字或图标反馈。选中状态不只依赖颜色。正文保持清楚对比度，长脚本不能出现横向滚动。

## 9 相邻步骤衔接与实施优先级

### 图6 商品确认页的小范围调整

保留现有商品与人物选择、商品图片、名称、描述和卖点确认方式。本次不重做整个信息填写流程。

从第一步移来的原商品与原人物详细资料，在这里通过“查看原商品”“查看原人物”按需展开。默认优先看到正在替换的对象及新对象；无须重新铺开原片的全部外观和环境说明。

关系图对于多商品、多人物有帮助；单商品场景可以弱化为清楚的替换关系，减少关系图占据过多可用空间。是否调整整个关系图可单独评估，不阻塞本次结果页优化。

截图中的参考视频没有口播：若产品当前只支持沿用这一形式，底部不应继续让用户选择一个看似会产生口播的语言；若支持新增口播，需显式选择“添加口播”后再出现语言设置。不要从“选择了英语”推断用户要新增口播。

### 图7 视频结果页的小范围调整

保留播放、下载、再次生成与历史结果。只读阶段将“返回修改脚本”调整为“返回脚本”，编辑开放后再使用“修改脚本”。

每条结果对应其生成时使用的脚本与设置。用户返回修改后，旧结果仍可查看；新视频完成后再产生新结果，避免同一版本中混用不同脚本。

继续保留生成成功这一任务状态，但不将它表达为“商品还原通过”或“效果已验证”。

### 分期交付

| 优先级 | 交付内容 | 完成标准 |
| --- | --- | --- |
| P0 本期 | 三类页面字段删减合并；去掉重复策略和情绪曲线；明确只读态；无口播处理；中文名称统一 | 用户不进入详情即可理解结构并读完脚本主要内容 |
| P0 本期 | 第一阶段对象说明移到第二步；第三步保留口播、字幕、商品关键表达；底部操作分层 | 每份内容有明确所属位置，生成前关键信息可见 |
| P1 下一期 | 开放逐段口播编辑和独立字幕编辑，提供保存、取消、恢复与必要联动 | 用户只修改文案即可让新生成使用新内容 |
| P1 后续 | 开放关键画面描述编辑，与商品确认和版本状态保持一致 | 修改后不需要另改技术描述，旧视频不被误标为新版本 |
| 按验证结果决定 | 更复杂的段落重排、时长调整、局部重写与完整提示词编辑 | 有实际需求和可用能力后单独设计，不挤入当前主流程 |

### 明确本期不新增的负担

不要求用户完成阅读确认勾选，不增加逐段审批，不将专家模式设为默认，不要求用户填写所有原始分析字段，也不为了展示“分析深度”重新增加成组术语标签。

## 10 验收标准与下一步原型范围

### 页面验收

| 检查项 | 可检查的标准 |
| --- | --- |
| 第一屏重点 | 可看到页面任务、视频或商品标识、简短概览及第一段内容，主操作可找到 |
| 字段去重 | 同一段不再同时出现创意策略、创意描述、关键信息和完整画面长文四种解释 |
| 阅读层级 | 从主视图查看所需补充内容最多进入一层详情，无阶段与分镜嵌套折叠 |
| 整稿可读 | 新脚本每段画面要点和全部口播可连续阅读；独立字幕没有遗漏或混入拍法 |
| 事实完整 | 压缩前后的商品主体、关键动作、规格条件、品牌及独立画面文字保持一致 |
| 无口播状态 | 不显示空白口播框；无口播、识别失败、无声三种状态不混用 |
| 只读与编辑 | 未实现编辑时不出现可编辑提示或输入框；编辑入口仅随真实能力开放 |
| 参考与成片 | 第三步原片画面明确标注参考；尚未生成时没有暗示已出片的预览 |
| 时间与数量 | 段落时间顺序正确、精度统一；段落数量与列表一致，不混用技术镜头数 |
| 视口与访问 | 常用桌面视口正文清晰、无横向滚动或底部遮挡；键盘可到达关键操作 |

### 验证优化是否有用

建议邀请5–8名目标用户，用旧版与新版完成相同任务：说出视频主要表达、找到某段口播、检查新商品在首段和收尾的呈现，并进入下一步。使用两条难度接近的素材，交替测试顺序。

记录完成时间、关键内容遗漏、误认为可编辑的次数，以及是否必须打开补充详情才能完成主要任务。以现版形成基线，再决定目标；当前方案不预先宣称能提升固定比例的转化或生成通过率。

### 下一步原型示例范围

1. **素材分析结果页：** 有口播素材，展示创意概览、借鉴点、段落和时间定位。
2. **复刻第一步：** 本次电动车素材，展示参考视频、复刻思路与四段紧凑结构。
3. **新脚本确认页：** 无口播版本，验证画面内容可通读、无空框和清楚的生成操作。
4. **新脚本编辑状态：** 后续有口播版本，展示一个段落的口播及画面编辑；明确标注为后续能力。

本次先以字段与呈现方案供评审；原型示例在下一步制作，图6与图7仅在需要说明衔接时补充局部示例。

### 设计依据

信息层级采用主要任务内容优先、次要内容按需查看的思路。参考 Nielsen Norman Group 的 [Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/)。本方案中的具体字段取舍根据上述页面任务制定，并不由通用原则直接决定。

口播、画面要点与参考片段保持就近可见，减少用户往返后凭记忆核对。参考 Nielsen Norman Group 的 [Memory Recognition and Recall in User Interfaces](https://www.nngroup.com/articles/recognition-and-recall/)。本方案效果仍需通过实际任务验证。
